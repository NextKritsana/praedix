Summary Digital Forensis

เอกสารฉบับนี้สังเคราะห์ข้อมูลเชิงลึกเกี่ยวกับนิติวิทยาศาสตร์ดิสก์ (Disk Forensics) โดยมุ่งเน้นที่องค์ประกอบพื้นฐานของระบบจัดเก็บข้อมูลในคอมพิวเตอร์และกระบวนการเริ่มต้นทำงานของระบบปฏิบัติการ Windows เนื้อหาหลักครอบคลุมถึงกระบวนการบูตที่แตกต่างกันระหว่างระบบที่ใช้ BIOS และ UEFI, การวิเคราะห์โครงสร้างเชิงลึกของ Master Boot Record (MBR) และ GUID Partition Table (GPT) รวมถึงแนวทางปฏิบัติในการวิเคราะห์พาร์ติชัน MBR

ประเด็นสำคัญที่ได้จากการวิเคราะห์มีดังนี้:

• กระบวนการบูตของ Windows: ระบบที่ใช้ BIOS จะอาศัย bootmgr ในการโหลดระบบปฏิบัติการ ในขณะที่ระบบ UEFI ซึ่งเป็นมาตรฐานใหม่กว่า จะใช้ bootmgfw.efi (Boot Manager) เพื่อเริ่มต้นกระบวนการและเรียกใช้ winload.efi (Bootloader) เพื่อโหลดเคอร์เนลของ Windows เข้าสู่หน่วยความจำ

Master Boot Record (MBR): เป็นโครงสร้างการแบ่งพาร์ติชันแบบดั้งเดิม มีขนาด 512 ไบต์ ประกอบด้วย Boot Code (446 ไบต์), ตารางพาร์ติชัน (64 ไบต์) และ Signature (2 ไบต์) MBR มีข้อจำกัดที่สำคัญคือรองรับพาร์ติชันหลักได้สูงสุดเพียง 4 พาร์ติชัน และรองรับขนาดดิสก์ได้ไม่เกิน 2TB เพื่อแก้ไขข้อจำกัดนี้จึงมีการใช้ Extended Partition และ Extended Boot Record (EBR) เพื่อสร้าง Logical Partition เพิ่มเติม

GUID Partition Table (GPT): เป็นมาตรฐานที่ทันสมัยกว่า MBR ออกแบบมาเพื่อรองรับอุปกรณ์จัดเก็บข้อมูลขนาดใหญ่และจำนวนพาร์ติชันที่มากขึ้น โดยสามารถรองรับพาร์ติชันได้สูงสุด 128 พาร์ติชันและขนาดดิสก์ตามทฤษฎีได้ถึง 9.4 ZB (Zettabytes) GPT มีความยืดหยุ่นและปลอดภัยกว่า MBR เนื่องจากมีการจัดเก็บสำเนาของ Header และตารางพาร์ติชันไว้ทั้งส่วนต้นและส่วนท้ายของดิสก์เพื่อการกู้คืนข้อมูล

เครื่องมือ FTK Imager และแสดงขั้นตอนการวิเคราะห์ตารางพาร์ติชัน MBR ด้วยตนเอง โดยการอ่านค่า Starting LBA Address และ Total Sectors เพื่อระบุตำแหน่งและขนาดของแต่ละพาร์ติชันบนดิสก์

ระบบที่ใช้ BIOS (Legacy)

ในระบบที่ใช้ BIOS กระบวนการบูตจะเริ่มต้นด้วยไฟล์ bootmgr

• หน้าที่: ทำหน้าที่เป็น Bootloader สำหรับ Windows

• การทำงาน: BIOS จะค้นหาและโหลด bootmgr จากเซกเตอร์แรกของ Master Boot Record (MBR) หรือจากพาร์ติชันที่สามารถบูตได้ จากนั้น bootmgr จะรับผิดชอบในการแสดงเมนูให้ผู้ใช้เลือกระบบปฏิบัติการ (ในกรณีที่มีหลายระบบ) หรือโหลดระบบปฏิบัติการที่เป็นค่าเริ่มต้น

• ตำแหน่ง: โดยทั่วไปจะอยู่ในไดเรกทอรีราก (Root Directory) ของไดรฟ์ระบบ

ระบบที่ใช้ UEFI

ในระบบที่ใช้ UEFI กระบวนการบูตมีความซับซ้อนกว่าและเกี่ยวข้องกับไฟล์หลักสองไฟล์คือ bootmgfw.efi และ winload.efi

ไฟล์สำคัญที่เกี่ยวข้อง:

• ntoskrnl.exe: เคอร์เนล (Kernel) หรือแกนหลักของระบบปฏิบัติการ Windows NT

• hal.dll: Hardware Abstraction Layer Dynamic Link Library, ไลบรารีที่ทำหน้าที่เป็นตัวกลางระหว่างฮาร์ดแวร์และซอฟต์แวร์

• .efi (Extensible Firmware Interface): มาตรฐานอินเทอร์เฟซสำหรับเฟิร์มแวร์ที่ใช้ในระหว่างกระบวนการบูตคอมพิวเตอร์

2. โครงสร้าง Master Boot Record (MBR)

MBR คือโครงสร้างข้อมูลขนาด 512 ไบต์ที่อยู่ในเซกเตอร์แรกสุดของอุปกรณ์จัดเก็บข้อมูล ทำหน้าที่เก็บข้อมูลเกี่ยวกับการแบ่งพาร์ติชันและโค้ดสำหรับเริ่มต้นกระบวนการบูต

2.1 องค์ประกอบของ MBR

2.2 โครงสร้าง Partition Table Entry

ตารางพาร์ติชันของ MBR ประกอบด้วย Entry 4 รายการ แต่ละรายการมีขนาด 16 ไบต์ ใช้สำหรับอธิบายข้อมูลของพาร์ติชัน 1 พาร์ติชัน

2.3 Extended Partition และ Extended Boot Record (EBR)

เนื่องจาก MBR รองรับพาร์ติชันหลักได้เพียง 4 พาร์ติชัน จึงมีการใช้ Primary Extended Partition เป็นวิธีแก้ปัญหา

• Extended Partition: เป็นพาร์ติชันพิเศษที่ไม่สามารถใช้บูตระบบปฏิบัติการได้โดยตรง แต่ทำหน้าที่เป็น "พื้นที่" สำหรับสร้างพาร์ติชันเพิ่มเติมที่เรียกว่า Logical Partitions ดิส E,D,C

• Extended Boot Record (EBR): เป็นโครงสร้างข้อมูลที่คล้ายกับ MBR แต่จะอยู่ภายใน Extended Partition ทำหน้าที่จัดการข้อมูลของ Logical Partitions โดยแต่ละ EBR จะเก็บข้อมูลของ Logical Partition หนึ่งรายการ และมีตัวชี้ (link) ไปยัง EBR ถัดไปในลักษณะลูกโซ่ (Chained) เพื่อให้สามารถสร้าง Logical Partition ได้หลายรายการ

3.โครงสร้าง GUID Partition Table (GPT)

GPT เป็นมาตรฐานการแบ่งพาร์ติชันที่ทันสมัย ถูกออกแบบมาเพื่อทดแทน MBR และแก้ไขข้อจำกัดต่างๆ โดยเฉพาะการรองรับอุปกรณ์จัดเก็บข้อมูลขนาดใหญ่

3.1 เปรียบเทียบ MBR และ GPT

3.2 โครงสร้างโดยรวมของดิสก์แบบ GPT

1. Protective MBR (LBA 0): MBR แบบพิเศษที่สร้างขึ้นเพื่อป้องกันไม่ให้เครื่องมือรุ่นเก่าที่รู้จักแต่ MBR มาแก้ไขข้อมูลบนดิสก์ GPT โดยจะแสดงผลว่าดิสก์มีพาร์ติชันเดียวครอบคลุมพื้นที่ทั้งหมด

2. Primary GPT Header (LBA 1): Header หลักที่เก็บข้อมูลสำคัญเกี่ยวกับดิสก์และตำแหน่งของตารางพาร์ติชัน

3. Primary GPT Partition Entries (LBA 2-33): ตารางหลักที่เก็บข้อมูลของพาร์ติชันทั้งหมด (โดยทั่วไปจะสำรองพื้นที่สำหรับ 128 entries) ตารางหลักเก็บข้อมูล

4. Data Partitions: พื้นที่จัดเก็บข้อมูลจริงของพาร์ติชันต่างๆ

5. Secondary GPT Partition Entries and Header: สำเนาของตารางพาร์ติชันและ GPT Header ที่จัดเก็บไว้ที่ส่วนท้ายของดิสก์เพื่อใช้ในการกู้คืนหากส่วนหลักเสียหาย

3.3 โครงสร้าง GPT Header (92 ไบต์)

GPT Header ประกอบด้วยข้อมูลเมตาดาต้าที่สำคัญเกี่ยวกับดิสก์และโครงสร้างพาร์ติชัน

• Signature ('EFI PART'): 8 ไบต์, ใช้ระบุว่าเป็น GPT Header

• Revision Number: 4 ไบต์, หมายเลขเวอร์ชันของ Header

• Header Size: 4 ไบต์, ขนาดของ Header (ปกติคือ 92 ไบต์)

• CRC32 of Header: 4 ไบต์, ค่า Checksum สำหรับตรวจสอบความสมบูรณ์ของ Header

• Current LBA: 8 ไบต์, ตำแหน่ง LBA ของ Header นี้

• Backup LBA: 8 ไบต์, ตำแหน่ง LBA ของ Header สำรอง

• First Usable LBA for partitions: 8 ไบต์, LBA แรกที่สามารถใช้สร้างพาร์ติชันได้

• Last Usable LBA: 8 ไบต์, LBA สุดท้ายที่สามารถใช้สร้างพาร์ติชันได้

• Disk GUID: 16 ไบต์, ตัวระบุที่ไม่ซ้ำกันสำหรับดิสก์นี้

• Starting LBA of array of partition entries: 8 ไบต์, ตำแหน่งเริ่มต้นของตารางพาร์ติชัน

• Number of partition entries: 4 ไบต์, จำนวน Entry ทั้งหมดที่จองไว้ในตาราง

• Size of a single partition entry: 4 ไบต์, ขนาดของแต่ละ Entry (ปกติคือ 128 ไบต์)

• CRC32 of partition entries array: 4 ไบต์, ค่า Checksum สำหรับตารางพาร์ติชันทั้งหมด

3.4 โครงสร้าง GPT Partition Entry (128 ไบต์)

แต่ละ Entry จะให้ข้อมูลรายละเอียดของหนึ่งพาร์ติชัน

• Partition Type GUID: 16 ไบต์, GUID ที่ระบุประเภทของพาร์ติชัน (เช่น EFI System Partition, Microsoft Basic Data)

• Unique Partition GUID: 16 ไบต์, GUID ที่ไม่ซ้ำกันสำหรับพาร์ติชันนี้โดยเฉพาะ

• First LBA: 8 ไบต์, ตำแหน่ง LBA เริ่มต้นของพาร์ติชัน

• Last LBA: 8 ไบต์, ตำแหน่ง LBA สิ้นสุดของพาร์ติชัน

• Attribute Flags: 8 ไบต์, ค่าสถานะต่างๆ ของพาร์ติชัน เช่น System Partition, Bootable, Read-Only, Hidden

• Partition Name: 72 ไบต์, ชื่อของพาร์ติชันในรูปแบบ Unicode (UTF-16LE)

4. การวิเคราะห์พาร์ติชัน MBR (ภาคปฏิบัติ)

เอกสารได้นำเสนอขั้นตอนการดึงข้อมูลดิสก์ (Image Dump) และการวิเคราะห์โครงสร้างพาร์ติชัน MBR ด้วยตนเอง

4.1 ขั้นตอนการสร้าง Disk Image ด้วย FTK Imager สร้างสำเนาแบบไฟล์อิมเมจ

1. Create Disk Image: เปิดโปรแกรมแล้วเลือกเมนู File > Create Disk Image

2. Select Source: เลือกว่าจะสร้างอิมเมจจาก Physical Drive (ทั้งดิสก์) หรือ Logical Drive (เฉพาะพาร์ติชัน)

3. Select Drive: เลือกไดรฟ์เป้าหมายที่ต้องการทำสำเนา

4. Add Image Destination: กำหนดประเภทของไฟล์อิมเมจ (เช่น RAW, E01) และระบุข้อมูลประกอบ (Evidence Item Information)

5. Set Destination: เลือกโฟลเดอร์ปลายทางและตั้งชื่อไฟล์อิมเมจ

6. Start: เริ่มกระบวนการสร้างอิมเมจ

7. Add Evidence Item: หลังจากสร้างเสร็จสิ้น ให้เปิดไฟล์อิมเมจที่ได้มาใน FTK Imager โดยใช้เมนู File > Add Evidence Item เพื่อเริ่มการวิเคราะห์

4.2 ขั้นตอนการวิเคราะห์ Partition Table ด้วยตนเอง

เมื่อเปิดไฟล์อิมเมจแล้ว การวิเคราะห์จะเริ่มต้นที่ MBR ซึ่งอยู่ที่ Offset 0 ของดิสก์

1. ระบุตำแหน่ง Partition Table: ตารางพาร์ติชันจะอยู่ที่ Offset 0x1BE ถึง 0x1FD (รวม 64 ไบต์)

2. วิเคราะห์ Partition Entry #1:

◦ อ่านค่า 16 ไบต์แรกของตาราง (ที่ Offset 0x1BE)

◦ ดึงค่า Starting LBA address (อยู่ที่ไบต์ที่ 9-12 ของ Entry)

◦ ดึงค่า Total Sectors (อยู่ที่ไบต์ที่ 13-16 ของ Entry)

3. ไปยังจุดเริ่มต้นของพาร์ติชัน:

◦ ใช้ฟังก์ชัน "Go to Offset" ในโปรแกรมวิเคราะห์

◦ ป้อนค่า Starting LBA ที่ได้จากขั้นตอนที่ 2 (โดยต้องระบุหน่วยเป็นเซกเตอร์) เพื่อกระโดดไปยังตำแหน่งเริ่มต้นของข้อมูลในพาร์ติชันนั้น

4. วิเคราะห์พาร์ติชันถัดไป:

◦ ตำแหน่งเริ่มต้นของพาร์ติชันที่สองสามารถคำนวณได้จาก (Starting LBA ของพาร์ติชันแรก) + (Total Sectors ของพาร์ติชันแรก)

◦ หรืออ่านค่า Starting LBA address จาก Partition Entry #2 โดยตรง

◦ ทำซ้ำขั้นตอนนี้สำหรับ Entry ที่เหลือ

ตัวอย่างข้อมูลจากตารางพาร์ติชัน: (ข้อมูลตัวเลขจาก Source Context เพื่อการอ้างอิง)

หมายเหตุ: การคำนวณตำแหน่งจริงต้องนำค่า LBA หรือ Sector ไปคูณด้วยขนาดของเซกเตอร์ (โดยทั่วไปคือ 512 ไบต์) เพื่อให้ได้ค่า Offset เป็นไบต์
