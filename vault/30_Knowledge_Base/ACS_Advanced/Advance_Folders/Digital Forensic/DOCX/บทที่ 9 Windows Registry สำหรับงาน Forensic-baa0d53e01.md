# บทที่ 9 Windows Registry สำหรับงาน Forensic

- Source: [บทที่ 9 Windows Registry สำหรับงาน Forensic.docx](file:///E:/ProJect/ACS%20File/advance/Digital%20Forensic/%E0%B8%9A%E0%B8%97%E0%B8%97%E0%B8%B5%E0%B9%88%209%20Windows%20Registry%20%E0%B8%AA%E0%B8%B3%E0%B8%AB%E0%B8%A3%E0%B8%B1%E0%B8%9A%E0%B8%87%E0%B8%B2%E0%B8%99%20Forensic.docx)

บทที่ 9 Windows Registry สำหรับงาน Forensic

บทสรุปสำหรับผู้บริหาร

เอกสารฉบับนี้สังเคราะห์ข้อมูลสำคัญเกี่ยวกับ Windows Registry ซึ่งเป็นฐานข้อมูลกลางที่มีโครงสร้างแบบลำดับชั้น ใช้สำหรับจัดเก็บข้อมูลการกำหนดค่าที่สำคัญของระบบปฏิบัติการ Windows คุณลักษณะเด่นของ Registry คือเป็นแบบ "ไม่ลบเลือน" (Non-volatile) หมายความว่าข้อมูลจะยังคงอยู่แม้จะปิดเครื่องไปแล้ว ทำให้เป็นแหล่งข้อมูลที่สำคัญอย่างยิ่งสำหรับงาน Forensic Registry ประกอบด้วยส่วนประกอบหลักที่เรียกว่า "Hives" ซึ่งเป็นไฟล์ทางกายภาพที่เก็บข้อมูลการตั้งค่าต่างๆ ตั้งแต่โปรไฟล์ผู้ใช้แต่ละรายไปจนถึงการกำหนดค่าฮาร์ดแวร์และซอฟต์แวร์ทั้งระบบ โครงสร้างหลักของ Registry แบ่งออกเป็น 5 Root Keys หลัก ได้แก่ HKEY_CLASSES_ROOT, HKEY_CURRENT_USER, HKEY_LOCAL_MACHINE, HKEY_USERS, และ HKEY_CURRENT_CONFIG การวิเคราะห์ Registry อาศัยเครื่องมือต่างๆ ตั้งแต่ Regedit ที่มาพร้อมกับ Windows ไปจนถึงเครื่องมือเฉพาะทางสำหรับงาน Forensic เช่น Registry Explorer (GUI) และ RECmd (Command-line) ซึ่งช่วยให้นักวิเคราะห์สามารถตรวจสอบ ติดตามประวัติการเปลี่ยนแปลง และกู้คืนข้อมูลที่ถูกลบได้

--------------------------------------------------------------------------------

1. ความเข้าใจพื้นฐานเกี่ยวกับ Windows Registry

Windows Registry เป็นฐานข้อมูลกลางที่จัดการข้อมูลสำคัญทั้งหมดของระบบปฏิบัติการ Windows รวมถึงข้อมูลซอฟต์แวร์ ฮาร์ดแวร์ และข้อมูลระบบอื่นๆ

โครงสร้างและลักษณะเฉพาะ

โครงสร้างแบบลำดับชั้น (Hierarchical Structure): Registry จัดระเบียบข้อมูลในรูปแบบของคีย์ (Keys) และค่า (Values) คีย์สามารถซ้อนกันเป็นลำดับชั้นได้เหมือนโฟลเดอร์ ในขณะที่ค่าทำหน้าที่เก็บข้อมูลจริงเหมือนไฟล์ โครงสร้างนี้มีประสิทธิภาพในการจัดหมวดหมู่ จัดเก็บ และเรียกค้นข้อมูล

Hive: คือส่วนประกอบทางกายภาพของ Registry ซึ่งเป็นไฟล์ที่บรรจุข้อมูลบางส่วนหรือทั้งหมดของ Registry

ฐานข้อมูล (Database): ทำหน้าที่เป็นฐานข้อมูลสำหรับจัดการข้อมูลที่สำคัญของระบบ

ไม่ลบเลือน (Non-volatile): ข้อมูลใน Registry จะถูกเก็บรักษาไว้อย่างถาวรและไม่หายไปเมื่อปิดเครื่อง เนื่องจากเป็นข้อมูลที่สำคัญต่อการทำงานของระบบ

การสะสมของข้อมูล (Data Accumulation): ข้อมูลที่ไม่ได้ใช้งานหรือไม่จำเป็นจะยังคงสะสมอยู่ใน Registry ซึ่งอาจส่งผลให้ประสิทธิภาพของระบบลดลงได้

วัตถุประสงค์และหน้าที่หลัก

จัดการโปรไฟล์ผู้ใช้: จัดเก็บข้อมูลเกี่ยวกับโปรไฟล์ของผู้ใช้ รวมถึงการตั้งค่าส่วนบุคคล ตัวแปรสภาพแวดล้อม และโปรแกรมที่ติดตั้ง

รวบรวมข้อมูลการตั้งค่าไว้ที่ส่วนกลาง: จัดการข้อมูลการกำหนดค่าสำหรับฮาร์ดแวร์และซอฟต์แวร์ของระบบปฏิบัติการไว้ในที่เดียว

บันทึกการตั้งค่าระบบ: จัดเก็บข้อมูลการกำหนดค่าสำหรับฮาร์ดแวร์ การตั้งค่าสำหรับซอฟต์แวร์ที่ติดตั้ง และตัวแปรสภาพแวดล้อมของระบบ

จัดการการกำหนดค่าระบบปฏิบัติการ: จัดการส่วนประกอบที่สำคัญของระบบปฏิบัติการ เช่น ข้อมูลเกี่ยวกับกระบวนการบูต, บริการของระบบ (System Services) และไดรเวอร์ฮาร์ดแวร์

2. โครงสร้างหลักของ Windows Registry

โครงสร้างของ Registry ประกอบด้วยส่วนประกอบหลักที่เรียกว่า Hives หรือ Root Keys ซึ่งแต่ละส่วนมีหน้าที่แตกต่างกันไป

Registry Hives (Root Keys)

ไฟล์ Hive ทางกายภาพ

Registry Hives ถูกจัดเก็บเป็นไฟล์จริงในระบบปฏิบัติการ โดยมีตำแหน่งหลักอยู่ที่ %systemroot%\system32\config\ การจับคู่ระหว่าง Root Keys และไฟล์ทางกายภาพมีดังนี้:

HKLM: αντιστοιχεί σε αρχεία system, software, security, sam

HKU: αντιστοιχεί σε αρχεία default, ntuser.dat (ซึ่งสอดคล้องกับ SID ของผู้ใช้)

Security Identifier (SID)

SID (Security Identifier) คือตัวระบุเฉพาะที่ใช้ในการระบุผู้ใช้ กลุ่มผู้ใช้ และหน่วยความปลอดภัยอื่นๆ ในระบบปฏิบัติการ Microsoft Windows SID มีบทบาทสำคัญในงานด้านความปลอดภัยและใน Access Control Lists (ACLs)

รูปแบบของ SID: ประกอบด้วยชุดของตัวเลขในรูปแบบ S-1-5-21-3623811015-3361044348-30300820-1013

S: คำนำหน้าที่แสดงว่าเป็น SID

1: หมายเลขเวอร์ชันของ SID

5: ตัวระบุเฉพาะสำหรับองค์กรที่ออก SID (โดยทั่วไป 5 หมายถึง Windows Security Authority)

ตัวเลขที่เหลือ: ใช้เพื่อระบุโดเมนและผู้ใช้ที่เฉพาะเจาะจง

SID ที่สำคัญ:

S-1-5-18: SystemProfile

S-1-5-19: LocalService SID

S-1-5-20: NetworkServices SID

S-1-5-21: User SID (เช่น 500 สำหรับ Administrator, 1000 สำหรับผู้ใช้ที่มีสิทธิพิเศษ, 1001 สำหรับผู้ใช้ทั่วไป)

3. ส่วนประกอบของ Registry: คีย์และค่า

Registry ประกอบด้วยสององค์ประกอบหลักคือ คีย์ (Keys) และ ค่า (Values)

คีย์ (Keys): เป็นหน่วยโครงสร้างของ Registry เปรียบเสมือน "โฟลเดอร์" คีย์สามารถแบ่งออกเป็น Root Key (Master Key) และ Sub Key (Derived Key) ที่อยู่ภายใต้คีย์อื่น

ค่า (Values): เป็นข้อมูลจริงที่จัดเก็บอยู่ภายในคีย์ เปรียบเสมือน "ไฟล์" ซึ่งประกอบด้วย 3 ส่วนคือ Value - Data Type - Data

ประเภทข้อมูลใน Registry (Registry Data Types)

Registry รองรับประเภทข้อมูลหลายรูปแบบเพื่อจัดเก็บข้อมูลการกำหนดค่าที่แตกต่างกันไป

4. เครื่องมือและการจัดการ Registry

การเข้าถึงและวิเคราะห์ Registry สามารถทำได้ผ่านเครื่องมือหลายชนิด

Regedit (Registry Editor)

เป็นเครื่องมือแก้ไข Registry ที่มาพร้อมกับ Windows อนุญาตให้ผู้ใช้สามารถดู, แก้ไข, สร้าง และลบคีย์และค่าได้โดยตรง นอกจากนี้ยังสามารถใช้ในการสำรองข้อมูล Registry ได้โดยทำตามขั้นตอนต่อไปนี้:

เปิด Regedit

ไปที่เมนู File -> Export

เลือกระยะที่ต้องการ (ทั้งหมดหรือสาขาที่เลือก)

บันทึกไฟล์ไปยังตำแหน่งที่ต้องการ

เครื่องมือวิเคราะห์ Registry สำหรับงาน Forensic

สำหรับงานวิเคราะห์เชิงลึก มีเครื่องมือเฉพาะทางที่พัฒนาขึ้นเพื่อวัตถุประสงค์นี้

Registry Explorer:

ประเภท: เครื่องมือแบบ GUI (Graphic User Interface)

ความสามารถ:

แสดงโครงสร้างของคีย์และค่าในรูปแบบต้นไม้

ติดตามและแสดงประวัติการเปลี่ยนแปลงของคีย์และค่า

กู้คืนคีย์และค่าที่ถูกลบได้

RECmd:

ผู้พัฒนา: Eric Zimmerman

ประเภท: เครื่องมือแบบ Command-line Interface

ความสามารถ: รองรับการค้นหาข้อมูลด้วย Query ที่ซับซ้อน

ตัวอย่างคำสั่ง:

แหล่งข้อมูลเหล่านี้ได้ระบุถึงเครื่องมือหลายชนิดที่ใช้ในการจัดการและวิเคราะห์ Windows Registry โดยสามารถแบ่งออกเป็นเครื่องมือแก้ไข (Editing Tool) ที่มาพร้อมกับ Windows และเครื่องมือวิเคราะห์ (Analysis Tools) เฉพาะทาง ดังนี้:

1. เครื่องมือแก้ไข Registry ที่มาพร้อมกับ Windows

• Regedit (Registry Editor):

◦ เป็นเครื่องมือแก้ไข Registry ที่จัดเตรียมไว้ให้โดย Windows

◦ หน้าที่หลักคือการอนุญาตให้ผู้ใช้ ดู (View), แก้ไข (modify), สร้าง (create), และลบ (delete) คีย์และค่าต่าง ๆ ใน Registry ได้โดยตรง

◦ นอกจากนี้ยังถูกใช้ในการสำรองข้อมูลค่า Registry โดยการเปิด Regedit และใช้คำสั่ง File - Export ที่มุมซ้ายบน เพื่อเลือกช่วงที่ต้องการสำรอง (ทั้งหมดหรือสาขาที่เลือก) และบันทึกไปยังตำแหน่งที่ต้องการ

2. เครื่องมือวิเคราะห์ Registry (Registry Analysis Tool)

เครื่องมือเหล่านี้ถูกกล่าวถึงภายใต้หัวข้อ "Registry Analysis Tool":

• RECmd:

◦ เป็นเครื่องมือที่สร้างโดย Eric Zimmerman

◦ สามารถหาแหล่งที่มาได้จาก Ericzimmerman.github.io

◦ มีการใช้งานในรูปแบบ Command Interface (ส่วนต่อประสานกับคำสั่ง) โดยมีการยกตัวอย่างการใช้คำสั่ง เช่น RECmd.exe -f "path to the hive" --(option to save)"path to save" -(options you want to save)f "filename you want" -(search options you want) "filters you want"

• Registry Explorer:

◦ เป็นเครื่องมือที่มีลักษณะเป็น GUI (ส่วนต่อประสานกราฟิกกับผู้ใช้)

◦ มีคุณสมบัติที่สำคัญหลายประการในการวิเคราะห์ทางนิติวิทยาศาสตร์ (Forensic) ดังนี้:

▪ รองรับ Search query (การค้นหาด้วยคำสั่ง)

▪ สามารถแสดง โครงสร้างแบบ Tree (tree structure) ของรายละเอียดคีย์และค่า

▪ สามารถ ติดตามและแสดงประวัติการเปลี่ยนแปลง ของคีย์และค่าต่าง ๆ

▪ สามารถ กู้คืนคีย์และค่าที่ถูกลบ (Recover deleted keys and values)

## Table 1

| Hive (Root Key) | คำอธิบาย |
| HKEY_CLASSES_ROOT | จัดเก็บข้อมูลการเชื่อมโยงไฟล์ (File Associations) และข้อมูล Object Linking and Embedding (OLE) เช่น การระบุว่าไฟล์นามสกุลหนึ่งจะถูกเปิดด้วยแอปพลิเคชันใด |
| HKEY_CURRENT_USER | จัดเก็บข้อมูลโปรไฟล์สำหรับผู้ใช้ที่กำลังล็อกอินอยู่ในปัจจุบัน เช่น การตั้งค่าส่วนตัว แอปพลิเคชันที่ติดตั้ง และการตั้งค่าส่วนบุคคลอื่นๆ |
| HKEY_LOCAL_MACHINE | จัดเก็บการตั้งค่าที่ใช้กับทั้งระบบ (System-wide) เช่น การตั้งค่าฮาร์ดแวร์ การตั้งค่าระบบปฏิบัติการ และการตั้งค่าสำหรับแอปพลิเคชันที่ติดตั้ง |
| HKEY_USERS | บรรจุโปรไฟล์ของผู้ใช้ทั้งหมด โดย Hive ของ HKEY_CURRENT_USER ของแต่ละบัญชีผู้ใช้จะถูกจัดเก็บไว้ที่นี่ |
| HKEY_CURRENT_CONFIG | จัดเก็บข้อมูลโปรไฟล์ฮาร์ดแวร์ปัจจุบันที่ใช้เมื่อระบบทำการบูต |
