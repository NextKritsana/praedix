บทที่ 8

การวิเคราะห์ Master File Table (MFT) ในระบบไฟล์ NTFS

MFT หรือ Master File Table เป็นส่วนประกอบที่สำคัญยิ่งในพื้นที่ของระบบไฟล์ (File System Area) ของสถาปัตยกรรม NTFS ใน Windows โดยทำหน้าที่เป็นศูนย์กลางในการจัดเก็บเมทาดาทาทั้งหมดที่เกี่ยวข้องกับไฟล์และไดเรกทอรีบนโวลุ่ม

โครงสร้างพื้นฐานของ NTFS ประกอบด้วย:

• Volume Boot Record (VBR): ส่วนเริ่มต้นของโวลุ่มที่เก็บข้อมูลสำคัญ เช่น ตำแหน่งเริ่มต้นของคลัสเตอร์ $MFT และ $MFTMirr

• Master File Table (MFT): ฐานข้อมูลหลักที่เก็บระเบียน (Entry) สำหรับทุกไฟล์และไดเรกทอรี

• Data Area: พื้นที่บนดิสก์ที่ใช้จัดเก็บเนื้อหาจริงของไฟล์

VBR จะระบุตำแหน่งเริ่มต้นของคลัสเตอร์ $MFT เพื่อให้ระบบปฏิบัติการสามารถเข้าถึงตารางไฟล์หลักได้ ตัวอย่างเช่น $MFT cluster start position = C0000 x (SPC = 8)

2. รายการ MFT พิเศษ (Special MFT Entries)

MFT Entries หมายเลข 0 ถึง 15 ถูกสงวนไว้สำหรับไฟล์เมทาดาทาของระบบ ซึ่งมีความสำคัญต่อการทำงานของ NTFS รายการที่สำคัญมีดังนี้:

รายการ MFT อื่นๆ ที่น่าสนใจ:

• Entry 24: $Quota: จัดการข้อมูลโควต้าการใช้งานดิสก์สำหรับผู้ใช้หรือกลุ่ม

• Entry 25: $ObjId: ให้ตัวระบุที่ไม่ซ้ำกันสำหรับไฟล์หรือไดเรกทอรี ซึ่งจะไม่เปลี่ยนแปลงแม้ไฟล์จะถูกย้าย

• Entry 26: $Reparse: จัดเก็บข้อมูลเกี่ยวกับ Reparse Points ซึ่งสนับสนุนการเปลี่ยนเส้นทางไฟล์ไปยังตำแหน่งอื่น

• Entry 27: $ReMetadata: จัดเก็บเมทาดาทาที่เกี่ยวข้องกับ Transactional NTFS (TxNTFS)

• Entry 28: $Repair: อาจมีข้อมูลที่ใช้สำหรับการซ่อมแซมระบบไฟล์

• Entry 30: $TxfLog: จัดการไฟล์ล็อกที่เกี่ยวข้องกับ Transactional NTFS

• Entry 33: $TxfLog.blf: ชื่อจริงของไฟล์ล็อก Transactional NTFS

• $UsnJrnl (ไม่เป็นทางการ): จัดการข้อมูลใน Update Sequence Number Journal ซึ่งติดตามการเปลี่ยนแปลงทั้งหมดที่เกิดขึ้นกับระบบไฟล์ มีประโยชน์ต่อการกู้คืนระบบและซอฟต์แวร์สำรองข้อมูล

3. โครงสร้างของ MFT Entry 1024 ไบต์

แต่ละ MFT Entry มีโครงสร้างภายในที่ประกอบด้วยส่วนต่างๆ ดังนี้:

• MFT Entry Header (48 ไบต์): ส่วนหัวที่เก็บข้อมูลพื้นฐานเกี่ยวกับ Entry

• Unused Space: พื้นที่ที่ไม่ได้ใช้งาน

3.2. แอตทริบิวต์ (Attributes)

แอตทริบิวต์คือหน่วยข้อมูลที่เก็บคุณสมบัติต่างๆ ของไฟล์ แต่ละประเภทมีรหัส (Attribute ID) ที่ไม่ซ้ำกันเป็นส่วนใหญ่ เพื่อให้ระบบสามารถค้นหาและตีความข้อมูลได้อย่างถูกต้อง

4. แนวคิดการจัดเก็บข้อมูลใน NTFS

4.1. Resident และ Non-Resident Attributes

• Resident Attributes: เมื่อข้อมูลของแอตทริบิวต์มีขนาดเล็กพอที่จะจัดเก็บโดยตรงภายในพื้นที่ของ MFT Entry ได้ วิธีนี้ให้ความเร็วในการเข้าถึงที่รวดเร็ว มักใช้กับเมทาดาทาพื้นฐาน เช่น ชื่อไฟล์ หรือไฟล์ขนาดเล็ก

• Non-Resident Attributes: เมื่อข้อมูลมีขนาดใหญ่เกินกว่าจะเก็บใน MFT Entry ได้ เนื้อหาข้อมูลจริงจะถูกจัดเก็บไว้ในคลัสเตอร์ต่างๆ บนดิสก์ MFT Entry จะเก็บเพียง "Data run" ซึ่งเป็นตัวชี้ไปยังตำแหน่งของข้อมูลนั้น

4.2. VCN, LCN, และ Sparse Files

• Virtual Cluster Number (VCN): ค่าที่ระบุตำแหน่งสัมพัทธ์ของคลัสเตอร์ภายในสตรีมข้อมูลของไฟล์ ใช้ในการอ้างอิงข้อมูลภายในไฟล์โดยไม่ขึ้นกับตำแหน่งจริงบนดิสก์

• Logical Cluster Number (LCN): ค่าที่แสดงถึงตำแหน่งคลัสเตอร์ทางกายภาพบนดิสก์ ใช้เพื่อค้นหาข้อมูลของ Non-Resident Attribute

• Sparse File: รูปแบบไฟล์ที่ออกแบบมาเพื่อประหยัดพื้นที่ดิสก์ โดยไม่มีการจัดสรรพื้นที่ทางกายภาพสำหรับส่วนของไฟล์ที่ไม่มีข้อมูลจริง (มีแต่ค่า 0) ระบบไฟล์จะให้ข้อมูลที่เต็มไปด้วย '0' เมื่อมีการอ่านพื้นที่ส่วนนั้น

4.3. Data Run และ Run List

• Data run: ส่วนของข้อมูลที่ต่อเนื่องกันบนดิสก์ซึ่งเป็นที่เก็บข้อมูลจริงของไฟล์ มีการจับคู่ระหว่าง VCN (ตำแหน่งเสมือนในไฟล์) กับ LCN (ตำแหน่งจริงบนดิสก์)

• Run List: โครงสร้างข้อมูลที่แสดงว่าบล็อกข้อมูลจริงของไฟล์กระจายตัวอยู่บนดิสก์อย่างไร ประกอบด้วยรายการของ 'Run' ทั้งหมดตามลำดับ สำหรับ Sparse File รายการ Run List จะแสดงเฉพาะพื้นที่ที่มีการจัดเก็บข้อมูลจริงเท่านั้น

5. การเปลี่ยนแปลงของ MFT และการรักษาความสมบูรณ์

• Fixup Array: กลไกสำคัญในการรักษาความสมบูรณ์ของข้อมูล โดยจะตรวจสอบข้อมูลใน 2 ไบต์สุดท้ายของแต่ละเซกเตอร์เพื่อให้แน่ใจว่าข้อมูลไม่เสียหายระหว่างการเขียน

• การสร้างไฟล์ (เช่น Test.txt):

1. เพิ่มเมทาดาทา (แอตทริบิวต์ต่างๆ) ลงในไฟล์ Test.txt

2. อัปเดตดัชนี (Index) ของไดเรกทอรี

• การลบไฟล์ (เช่น Test.txt):

1. ไฟล์ที่ถูกลบจะไม่ถูกลบออกไปทันที

2. ระเบียนของไฟล์ใน MFT จะถูกอัปเดตสถานะเป็น "deleted"

3. พื้นที่ดิสก์ที่เคยเก็บไฟล์จะถูกคืนสถานะ

4. $BITMAP จะได้รับการอัปเดตเพื่อแสดงว่าพื้นที่นั้นว่างแล้ว

5. $LogFile จะบันทึกธุรกรรม

6. ดัชนีของไดเรกทอรีที่ไฟล์เคยอยู่จะถูกอัปเดต
