# Summary Digital Forensis เอกสาร 5

- Source: [Summary Digital Forensis เอกสาร 5.docx](file:///E:/ProJect/ACS%20File/advance/Digital%20Forensic/Summary%20Digital%20Forensis%20%E0%B9%80%E0%B8%AD%E0%B8%81%E0%B8%AA%E0%B8%B2%E0%B8%A3%205.docx)

โครงสร้างของ FAT32 Volume ประกอบด้วย 5 ส่วนหลักเรียงตามลำดับดังนี้:

1. Boot Sector

2. File Allocation Table #1 (FAT #1)

3. File Allocation Table #2 (FAT #2)

4. Root Directory

5. Data Area

1. Boot Sector: พิมพ์เขียวของโวลุ่ม

Boot Sector คือส่วนแรกสุดของโวลุ่มและทำหน้าที่เป็น "พิมพ์เขียว" ที่เก็บข้อมูลเมตาดาต้าที่สำคัญทั้งหมดเกี่ยวกับโวลุ่มนั้น สำหรับนักวิเคราะห์ทางนิติวิทยาศาสตร์ Boot Sector คือจุดเริ่มต้นของการวิเคราะห์ทั้งหมด เพราะมีข้อมูลที่จำเป็นในการคำนวณตำแหน่งของโครงสร้างอื่นๆ

• ข้อมูลสำคัญใน Boot Sector:

◦ Bytes Per Sector: ขนาดของเซกเตอร์ (โดยทั่วไปคือ 512 ไบต์)

◦ Reserved Sector Count: จำนวนเซกเตอร์ที่สงวนไว้ตอนต้นของโวลุ่ม ซึ่งเป็นค่าที่ใช้เป็นจุดอ้างอิงแรกสุด

◦ FAT Size 32: ขนาดของตาราง FAT แต่ละตาราง

◦ Root Dir Cluster: คลัสเตอร์เริ่มต้นของ Root Directory

• ความสำคัญทางนิติวิทยาศาสตร์: หาก Boot Sector เสียหาย ระบบปฏิบัติการอาจไม่สามารถเข้าถึงโวลุ่มได้ แต่นักวิเคราะห์สามารถใช้ค่าจากสำเนาของ Boot Record (ที่ระบุตำแหน่งโดย Boot Record Backup Sec) หรือสร้างขึ้นใหม่จากค่ามาตรฐานเพื่อคำนวณตำแหน่งของ FAT และ Data Area เพื่อเริ่มกระบวนการกู้คืนข้อมูลได้

2. File Allocation Table (FAT): แผนที่เชื่อมโยงข้อมูล

FAT เป็นหัวใจของการจัดเก็บไฟล์ ทำหน้าที่เหมือนสารบัญที่ระบุว่าไฟล์แต่ละไฟล์ถูกเก็บไว้ในคลัสเตอร์ใดบ้าง และคลัสเตอร์เหล่านั้นเรียงต่อกันอย่างไร (เรียกว่า Cluster Chain)

• โครงสร้างซ้ำซ้อนเพื่อความน่าเชื่อถือ: FAT32 จะมีตาราง FAT สองชุด (FAT #1 และ FAT #2) ที่เก็บข้อมูลเหมือนกันทุกประการ การมีสำเนานี้มีไว้เพื่อ เพิ่มความน่าเชื่อถือ (reliability) และความสามารถในการกู้คืน (recoverability) ในกรณีที่ตารางชุดใดชุดหนึ่งเสียหาย ซึ่งเป็นประโยชน์อย่างมากในทางนิติวิทยาศาสตร์

• ความสำคัญทางนิติวิทยาศาสตร์: การวิเคราะห์ตาราง FAT ทำให้นักวิเคราะห์สามารถติดตามลำดับการจัดเรียงข้อมูลของไฟล์ (cluster chain) ได้ แม้ว่า Directory Entry ของไฟล์นั้นจะถูกลบไปแล้วก็ตาม นอกจากนี้ยังสามารถเห็นร่องรอยของไฟล์ที่ถูกเขียนทับบางส่วน (fragmentation) ได้

3. Root Directory และ Directory Entry: ป้ายชื่อและข้อมูลเมตาดาต้าของไฟล์

Root Directory คือไดเรกทอรีระดับบนสุดของโวลุ่ม ภายในไดเรกทอรีต่างๆ (รวมถึง Root Directory) จะประกอบด้วยโครงสร้างข้อมูลขนาด 32 ไบต์ที่เรียกว่า Directory Entry ซึ่งเก็บเมตาดาต้าทั้งหมดของไฟล์หรือไดเรกทอรีหนึ่งๆ

• ข้อมูลใน Directory Entry: ประกอบด้วย ชื่อไฟล์ (8 ไบต์), นามสกุล (3 ไบต์), คุณสมบัติไฟล์ (1 ไบต์), วันเวลาที่สร้าง/แก้ไข/เข้าถึงล่าสุด, ขนาดไฟล์ (4 ไบต์), และที่สำคัญที่สุดคือ หมายเลขคลัสเตอร์เริ่มต้นของไฟล์ (แบ่งเป็น High 2 bytes และ Low 2 bytes)

• ความสำคัญทางนิติวิทยาศาสตร์ (จุดที่สำคัญที่สุด): Directory Entry คือกุญแจสำคัญในการกู้คืนไฟล์ที่ถูกลบ เมื่อไฟล์ถูกลบในระบบ FAT32 ข้อมูลไฟล์ใน Data Area จะยังไม่ถูกลบไปในทันที แต่ระบบจะทำการเปลี่ยนแปลง Directory Entry ดังนี้:

◦ ไบต์แรกของชื่อไฟล์ใน Directory Entry จะถูกเปลี่ยนเป็นค่า 0xE5 เพื่อระบุว่าไฟล์นี้ "ถูกลบแล้ว"

◦ ข้อมูลเมตาดาต้าอื่นๆ เช่น ขนาดไฟล์, วันที่, และหมายเลขคลัสเตอร์เริ่มต้น มักจะยังคงอยู่เหมือนเดิม

◦ นักวิเคราะห์จะค้นหา Directory Entry ที่ขึ้นต้นด้วย 0xE5 จากนั้นใช้ข้อมูลขนาดไฟล์และคลัสเตอร์เริ่มต้นที่ยังเหลืออยู่เพื่อตามไปกู้คืนข้อมูลจาก Data Area กลับมาได้ ตราบใดที่ข้อมูลนั้นยังไม่ถูกเขียนทับ

4. Data Area: พื้นที่เก็บข้อมูลจริง

Data Area คือส่วนที่ใหญ่ที่สุดของโวลุ่ม เป็นที่สำหรับเก็บ เนื้อหาข้อมูลจริงๆ ของไฟล์และไดเรกทอรี พื้นที่นี้จะถูกแบ่งออกเป็นหน่วยที่เรียกว่า "คลัสเตอร์"

• ความสำคัญทางนิติวิทยาศาสตร์: เป็นพื้นที่เป้าหมายสุดท้ายในการกู้คืนข้อมูล นักวิเคราะห์จะใช้ข้อมูลจาก Directory Entry (หมายเลขคลัสเตอร์เริ่มต้น) และ FAT (ลำดับคลัสเตอร์ถัดไป) เพื่อระบุตำแหน่งและรวบรวมข้อมูลของไฟล์ที่ต้องการจากพื้นที่ส่วนนี้ ในกรณีที่ Directory Entry และ FAT เสียหายทั้งหมด นักวิเคราะห์ยังสามารถใช้เทคนิคที่เรียกว่า "File Carving" เพื่อสแกนหา Signature ของไฟล์ประเภทต่างๆ ในพื้นที่ Data Area โดยตรงได้

โดยสรุปแล้ว โครงสร้างของ FAT32 Volume มีความสัมพันธ์กันอย่างเป็นระบบสำหรับงานนิติวิทยาศาสตร์ดิสก์ โดยเริ่มจาก Boot Sector เพื่อทำความเข้าใจแผนผังทั้งหมด, ใช้ Directory Entry (โดยเฉพาะการมองหาเครื่องหมาย 0xE5) เพื่อหาข้อมูลเมตาดาต้าของไฟล์ที่ถูกลบ, จากนั้นใช้ FAT เพื่อติดตามลำดับการเรียงตัวของข้อมูล และสุดท้ายคือการเข้าไปดึงข้อมูลจริงจาก Data Area

การทำความเข้าใจกระบวนการทั้งสามนี้เป็นหัวใจสำคัญของงานนิติวิทยาศาสตร์ดิสก์สำหรับระบบไฟล์ FAT32 เพราะมันเผยให้เห็นถึง "ร่องรอยดิจิทัล" ที่ระบบไฟล์ทิ้งไว้ ซึ่งนักวิเคราะห์สามารถใช้เพื่อสืบสวนและกู้คืนหลักฐานได้

กระบวนการสร้างไฟล์ (File Creation Process)

เมื่อมีการสร้างไฟล์ใหม่ในโวลุ่ม FAT32 ระบบจะดำเนินการตามขั้นตอนที่เป็นระบบเพื่อจัดสรรพื้นที่และบันทึกข้อมูลเมตาดาต้า

1. ตรวจสอบข้อมูลโวลุ่ม (Check volume information): ระบบจะอ่านข้อมูลจากโครงสร้าง FSINFO (File System Information) เพื่อหาข้อมูลเกี่ยวกับพื้นที่ว่าง เช่น จำนวนคลัสเตอร์ที่ว่างอยู่ (Free Cluster Count) และตำแหน่งของคลัสเตอร์ว่างถัดไป (Next Free Cluster)

2. ค้นหาและจัดสรรพื้นที่ว่าง (Find unallocated area & Assign cluster): ระบบจะใช้ข้อมูลจากขั้นตอนแรกเพื่อหาคลัสเตอร์ที่ว่างใน Data Area และจัดสรรให้กับไฟล์ใหม่นี้

3. เขียนข้อมูลลงคลัสเตอร์ (Write data): เนื้อหาจริงๆ ของไฟล์จะถูกเขียนลงในคลัสเตอร์ที่จัดสรรไว้ใน Data Area

4. สร้าง Directory Entry: ระบบจะหาพื้นที่ว่างในไดเรกทอรีที่เหมาะสมและสร้าง Directory Entry ซึ่งเป็นโครงสร้างข้อมูลขนาด 32 ไบต์ขึ้นมาใหม่สำหรับไฟล์นี้

5. อัปเดตข้อมูลใน Directory Entry: ข้อมูลเมตาดาต้าที่สำคัญจะถูกบันทึกลงใน Directory Entry ได้แก่:

◦ ชื่อไฟล์ (8 ไบต์) และนามสกุล (3 ไบต์)

◦ คุณสมบัติของไฟล์ (File Attributes)

◦ วันเวลาที่สร้าง, แก้ไข, และเข้าถึงล่าสุด

◦ หมายเลขคลัสเตอร์เริ่มต้นของไฟล์ (ซึ่งประกอบด้วย High 2 bytes และ Low 2 bytes)

◦ ขนาดไฟล์ (File Size) (4 ไบต์)

6. สร้าง Cluster Chain ในตาราง FAT: หากไฟล์มีขนาดใหญ่กว่าหนึ่งคลัสเตอร์ ระบบจะอัปเดตตาราง File Allocation Table เพื่อสร้างการเชื่อมโยง (chain) ระหว่างคลัสเตอร์ต่างๆ ที่ไฟล์นั้นใช้งานอยู่

กระบวนการลบไฟล์ (File Deletion Process)

นี่คือกระบวนการที่สำคัญที่สุดในมุมมองของนิติวิทยาศาสตร์ เพราะการลบไฟล์ใน FAT32 ไม่ได้เป็นการทำลายข้อมูลในทันที แต่เป็นการเปลี่ยนแปลงข้อมูลเมตาดาต้าเพียงเล็กน้อยเท่านั้น

1. ค้นหาไฟล์และ Directory Entry: ระบบจะค้นหา Directory Entry ที่ตรงกับไฟล์ที่ต้องการลบ

2. อัปเดต Directory Entry (จุดสำคัญที่สุด):

◦ ระบบจะเปลี่ยน ไบต์แรกของชื่อไฟล์ใน Directory Entry ให้เป็นค่า 0xE5

◦ เครื่องหมาย 0xE5 นี้ทำหน้าที่เป็น "ป้ายกำกับ" ที่บอกระบบปฏิบัติการว่า Directory Entry นี้ถูกลบแล้ว และพื้นที่ที่เคยใช้งานอยู่สามารถนำไปใช้ซ้ำได้

◦ ข้อมูลเมตาดาต้าอื่นๆ เช่น ขนาดไฟล์, วันที่, และโดยเฉพาะอย่างยิ่ง หมายเลขคลัสเตอร์เริ่มต้น มักจะยังคงอยู่เหมือนเดิม ไม่ได้ถูกลบไปด้วย

3. อัปเดตตาราง FAT: รายการที่อยู่ในตาราง File Allocation Table ที่เคยเชื่อมโยงคลัสเตอร์ของไฟล์นี้ไว้ จะถูกทำเครื่องหมายว่าเป็น "พื้นที่ว่าง" ซึ่งเป็นการตัดสายโซ่ (cluster chain) ของไฟล์นั้น

ความสำคัญทางนิติวิทยาศาสตร์: การที่ข้อมูลไฟล์ใน Data Area และเมตาดาต้าส่วนใหญ่ใน Directory Entry ยังคงอยู่ ทำให้การกู้คืนไฟล์เป็นไปได้สูง ตราบใดที่พื้นที่นั้นยังไม่ถูกเขียนทับด้วยข้อมูลใหม่

กระบวนการกู้คืนไฟล์ (File Recovery Process)

กระบวนการกู้คืนคือการย้อนรอยกระบวนการลบ โดยอาศัยร่องรอยที่ยังหลงเหลืออยู่

1. ค้นหา Directory Entry ที่ถูกลบ: นักวิเคราะห์จะสแกนหา Directory Entry ที่มี ไบต์แรกเป็นค่า 0xE5 นี่คือสัญญาณแรกที่บ่งชี้ว่าเคยมีไฟล์อยู่ตรงนี้

2. วิเคราะห์เมตาดาต้าที่เหลืออยู่: เมื่อพบ Directory Entry ที่ถูกลบแล้ว นักวิเคราะห์จะดึงข้อมูลสำคัญที่ยังคงอยู่ ได้แก่:

◦ หมายเลขคลัสเตอร์เริ่มต้น (Start Cluster Number): ได้มาจากการรวมค่า High และ Low 2 bytes

◦ ขนาดไฟล์ (File Size): ข้อมูลขนาดไฟล์ที่ยังสมบูรณ์

3. ติดตามไปยัง Data Area: ใช้หมายเลขคลัสเตอร์เริ่มต้นเพื่อระบุตำแหน่งแรกของข้อมูลไฟล์ใน Data Area

4. กู้คืนข้อมูลไฟล์: นักวิเคราะห์จะอ่านข้อมูลจาก Data Area โดยเริ่มจากคลัสเตอร์เริ่มต้นและอ่านไปตามจำนวนไบต์ที่ระบุไว้ใน File Size

5. ตรวจสอบความสมบูรณ์ของไฟล์ (File Integrity Check): หลังจากดึงข้อมูลออกมาแล้ว จะมีการตรวจสอบว่าไฟล์ที่กู้คืนมานั้นสมบูรณ์หรือไม่ หากไฟล์เดิมมีการกระจายตัว (fragmentation) และข้อมูลในตาราง FAT ถูกล้างไปแล้ว การกู้คืนอาจได้ข้อมูลมาเพียงบางส่วน หรือต้องใช้เทคนิคขั้นสูงอื่นเข้ามาช่วย

โดยสรุป แหล่งข้อมูลเหล่านี้ชี้ให้เห็นว่ากระบวนการจัดการไฟล์ของ FAT32 ทิ้งร่องรอยที่ชัดเจน โดยเฉพาะ เครื่องหมาย 0xE5 ใน Directory Entry ซึ่งเป็นกุญแจสำคัญที่ทำให้นักนิติวิทยาศาสตร์ดิสก์สามารถ "มองเห็น" และกู้คืนไฟล์ที่ผู้ใช้งานทั่วไปคิดว่าถูกลบไปอย่างถาวรแล้วได้

จากแหล่งข้อมูลที่ให้มา สามารถขยายความเกี่ยวกับ โครงสร้างของ Directory Entry (Directory Entry Structure) ในบริบทที่กว้างขึ้นของ นิติวิทยาศาสตร์ดิสก์ (Disk Forensics) สำหรับ FAT32 ได้อย่างละเอียดดังนี้ครับ

ในงานนิติวิทยาศาสตร์ดิสก์ การทำความเข้าใจโครงสร้าง Directory Entry ถือเป็นหัวใจสำคัญอย่างยิ่ง เพราะมันคือ "บัตรประจำตัว" ของไฟล์หรือไดเรกทอรีแต่ละรายการ ซึ่งเก็บข้อมูลเมตาดาต้าที่จำเป็นทั้งหมดไว้ และที่สำคัญที่สุดคือ มันเป็นแหล่งข้อมูลหลักที่นักวิเคราะห์ใช้ในการค้นหาและกู้คืนไฟล์ที่ถูกลบไปแล้ว

ลักษณะพื้นฐานของ Directory Entry

ตามที่แหล่งข้อมูลระบุ Directory Entry คือโครงสร้างข้อมูลขนาด 32 ไบต์ ที่ใช้เก็บข้อมูลเมตาดาต้าเกี่ยวกับไฟล์หรือไดเรกทอรี ทุกไฟล์และไดเรกทอรีจะมี Directory Entry อย่างน้อยหนึ่งรายการอยู่ภายในไดเรกทอรีแม่ของมัน รวมถึงใน Root Directory ด้วย

การแบ่งส่วนประกอบของโครงสร้าง 32 ไบต์

แหล่งข้อมูลได้แจกแจงโครงสร้าง 32 ไบต์นี้ออกเป็นส่วนต่างๆ ซึ่งแต่ละส่วนมีความสำคัญอย่างยิ่งในทางนิติวิทยาศาสตร์:

• File Name (8 ไบต์): เก็บชื่อไฟล์หลัก

• Extension (3 ไบต์): เก็บส่วนขยายหรือนามสกุลของไฟล์

• File Attributes (1 ไบต์): เก็บคุณสมบัติของไฟล์ เช่น อ่านอย่างเดียว (Read-only), ซ่อน (Hidden), หรือเป็นไดเรกทอรี

• Timestamps (รวม 10 ไบต์): เก็บข้อมูลวันเวลาที่สร้าง (Create Time/Date), วันเวลาที่เข้าถึงล่าสุด (Last Access Date), และวันเวลาที่แก้ไขล่าสุด (Write Time/Date)

• หมายเลขคลัสเตอร์เริ่มต้น (Start Cluster Number) (รวม 4 ไบต์):

◦ นี่คือข้อมูลที่สำคัญที่สุดชิ้นหนึ่งสำหรับนักวิเคราะห์

◦ ข้อมูลนี้จะถูกแบ่งเก็บเป็น 2 ส่วน คือ High 2 bytes of first cluster (16 บิตบน) และ Low 2 bytes of first cluster (16 บิตล่าง)

◦ เมื่อนำค่าทั้งสองส่วนมารวมกัน จะได้เป็นหมายเลขคลัสเตอร์เริ่มต้นขนาด 32 บิต ซึ่งทำหน้าที่เป็น "ตัวชี้" ไปยังตำแหน่งแรกใน Data Area ที่เนื้อหาจริงของไฟล์ถูกจัดเก็บไว้

• File Size (4 ไบต์): เก็บขนาดของไฟล์เป็นหน่วยไบต์ ซึ่งเป็นข้อมูลสำคัญอีกชิ้นที่ใช้ในการกู้คืน

ความสำคัญของ Directory Entry ในนิติวิทยาศาสตร์ดิสก์

ความสำคัญที่แท้จริงของโครงสร้างนี้ในงานนิติวิทยาศาสตร์อยู่ที่ การตีความค่าของไบต์แรกของชื่อไฟล์ ซึ่งแหล่งข้อมูลได้อธิบายไว้อย่างชัดเจน:

1. ไฟล์ที่ยังไม่ถูกลบ (A file that has not been deleted):

◦ สำหรับไฟล์หรือไดเรกทอรีที่ยังใช้งานอยู่ ไบต์แรกของ Directory Entry จะเป็น อักขระตัวแรกของชื่อไฟล์

◦ ค่านี้สามารถเป็นได้ตั้งแต่ 0x01 ถึง 0xFF ซึ่งสอดคล้องกับรหัส ASCII หรือชุดอักขระแบบขยาย

2. ไฟล์ที่ถูกลบ (Entries marked for deletion):

◦ นี่คือหัวใจสำคัญของการกู้คืนไฟล์ใน FAT32 เมื่อผู้ใช้สั่งลบไฟล์ ระบบปฏิบัติการจะ เปลี่ยนค่าไบต์แรกของ Directory Entry ของไฟล์นั้นให้เป็น 0xE5

◦ ค่า 0xE5 นี้ทำหน้าที่เป็น "เครื่องหมาย" หรือ "ป้ายกำกับ" ที่บอกให้ระบบไฟล์ทราบว่าไฟล์นี้ถูกลบไปแล้ว และพื้นที่ที่เคยใช้งานสามารถนำไปใช้ซ้ำได้

◦ สิ่งที่สำคัญที่สุดคือ: การเปลี่ยนแปลงนี้เกิดขึ้นแค่ที่ไบต์แรกเท่านั้น ข้อมูลเมตาดาต้าที่เหลืออีก 31 ไบต์ ซึ่งรวมถึง หมายเลขคลัสเตอร์เริ่มต้น และ ขนาดไฟล์ มักจะยังคงอยู่เหมือนเดิมไม่ได้ถูกลบไปด้วย

ในบริบทที่กว้างขึ้น การทำความเข้าใจโครงสร้างนี้ทำให้นักวิเคราะห์ทางนิติวิทยาศาสตร์สามารถ:

• ค้นหาไฟล์ที่ถูกลบ: โดยการสแกนหา Directory Entry ทั้งหมดที่มีไบต์แรกเป็นค่า 0xE5

• ระบุตำแหน่งข้อมูล: ใช้ หมายเลขคลัสเตอร์เริ่มต้น (Start Cluster Number) ที่ยังคงอยู่ใน Entry เพื่อชี้ไปยังตำแหน่งแรกของข้อมูลไฟล์ใน Data Area

• กำหนดขอบเขตข้อมูล: ใช้ ขนาดไฟล์ (File Size) ที่ยังคงอยู่ เพื่อคำนวณว่าจะต้องอ่านข้อมูลจาก Data Area เป็นจำนวนกี่ไบต์เพื่อกู้คืนไฟล์ให้สมบูรณ์

ดังนั้น Directory Entry Structure จึงไม่ได้เป็นเพียงโครงสร้างทางเทคนิค แต่เป็น แผนที่นำทางสำคัญ ที่ช่วยให้นักวิเคราะห์สามารถย้อนรอยกระบวนการลบและกู้คืนหลักฐานดิจิทัลที่ผู้ใช้งานทั่วไปคิดว่าหายไปอย่างถาวรแล้วได้สำเร็จ

ในระบบไฟล์ FAT32 โครงสร้าง Directory Entry ซึ่งมีขนาด 32 ไบต์ ทำหน้าที่เก็บข้อมูลเมตาดาทั้งหมดของไฟล์ อย่างไรก็ตาม ไบต์แรกสุด ของโครงสร้างนี้มีความสำคัญเป็นพิเศษในทางนิติวิทยาศาสตร์ เพราะมันไม่ได้เก็บข้อมูลชื่อไฟล์เสมอไป แต่ทำหน้าที่เป็น "ตัวบ่งชี้สถานะ" (Status Indicator) ที่บอกว่า Entry นั้นอยู่ในสถานะใด: เป็นไฟล์ที่ยังใช้งานอยู่, ถูกลบไปแล้ว, หรือเป็น Entry พิเศษ

แหล่งข้อมูลได้จำแนกความหมายของไบต์แรกนี้ออกเป็นสถานะต่างๆ ดังนี้:

1. สถานะ: ไฟล์ที่ยังไม่ถูกลบ (A file that has not been deleted)

• ค่าไบต์แรก: จะเป็น อักขระตัวแรกของชื่อไฟล์

• ช่วงของค่า: สามารถมีค่าได้ตั้งแต่ 0x01 ถึง 0xFF ซึ่งสอดคล้องกับรหัส ASCII มาตรฐานหรือชุดอักขระแบบขยาย

• ความสำคัญทางนิติวิทยาศาสตร์: เมื่อนักวิเคราะห์พบ Directory Entry ที่มีไบต์แรกอยู่ในช่วงค่านี้ จะหมายความว่า Entry ดังกล่าวเป็นตัวแทนของไฟล์หรือไดเรกทอรีที่ยังคงแอคทีฟและสามารถเข้าถึงได้ตามปกติในระบบไฟล์

2. สถานะ: ไฟล์ที่ถูกลบ (Entries marked for deletion)

• ค่าไบต์แรก: จะถูกตั้งค่าเป็น 0xE5

• ความสำคัญทางนิติวิทยาศาสตร์ (จุดที่สำคัญที่สุด):

◦ นี่คือร่องรอยดิจิทัลที่เป็นหัวใจของการกู้คืนไฟล์ใน FAT32 เมื่อมีการสั่งลบไฟล์ ระบบปฏิบัติการจะไม่ได้ลบข้อมูลทั้งหมดใน Directory Entry แต่จะทำการเปลี่ยนแปลงเพียงเล็กน้อย คือการเขียนทับไบต์แรกด้วยค่า 0xE5 เท่านั้น

◦ ค่า 0xE5 นี้ทำหน้าที่เป็น "เครื่องหมาย" หรือ "ป้ายกำกับ" ที่บอกระบบไฟล์ว่า Entry นี้ไม่ถูกต้องอีกต่อไป และพื้นที่ที่เคยใช้งานสามารถนำไปใช้ซ้ำได้

◦ สำหรับนักวิเคราะห์ การสแกนหา Directory Entry ที่มีไบต์แรกเป็น 0xE5 คือขั้นตอนแรกในการค้นหาไฟล์ที่ถูกลบ เนื่องจากข้อมูลเมตาด้าที่เหลืออีก 31 ไบต์ (เช่น ขนาดไฟล์ และหมายเลขคลัสเตอร์เริ่มต้น) มักจะยังคงอยู่ครบถ้วน ทำให้สามารถใช้ข้อมูลเหล่านี้เพื่อตามไปกู้คืนเนื้อหาไฟล์จาก Data Area ได้

3. สถานะพิเศษอื่นๆ

แหล่งข้อมูลยังได้กล่าวถึงค่าพิเศษอื่นๆ ของไบต์แรกที่นักวิเคราะห์อาจพบเจอ:

• ค่า 0x00: บ่งชี้ว่า ไม่มี Entry ที่ถูกต้องอีกต่อไป ณ ตำแหน่งนั้น และเป็นเครื่องหมายสิ้นสุดของรายการในไดเรกทอรี นักวิเคราะห์จะทราบว่าควรหยุดการค้นหาในไดเรกทอรีนั้นเมื่อเจอค่านี้

• ค่า 0x2E: บ่งชี้ว่าเป็น Entry พิเศษที่ชี้ไปยัง ไดเรกทอรีปัจจุบัน (".") หรือ ไดเรกทอรีแม่ ("..")

ในบริบทที่กว้างขึ้นของโครงสร้าง Directory Entry ไบต์แรกนี้จึงเปรียบเสมือน "สวิตช์" ที่ควบคุมการมองเห็นของไฟล์ในระบบปฏิบัติการ การเปลี่ยนแปลงค่าของไบต์นี้จากตัวอักษรปกติไปเป็น 0xE5 คือการ "ซ่อน" ไฟล์จากการมองเห็นของผู้ใช้ทั่วไป แต่สำหรับนักนิติวิทยาศาสตร์ดิจิทัล มันคือเบาะแสชิ้นสำคัญที่เปิดประตูไปสู่การกู้คืนหลักฐานที่ดูเหมือนจะสูญหายไปแล้ว

Start Cluster Number คือหนึ่งในข้อมูลเมตาดาต้าที่สำคัญที่สุดที่ถูกเก็บไว้ในโครงสร้าง Directory Entry. มันทำหน้าที่เป็น "ตัวชี้ตำแหน่ง" (pointer) หรือ "พิกัด" ที่เชื่อมโยงข้อมูลเมตาดาต้าของไฟล์เข้ากับเนื้อหาข้อมูลจริงของไฟล์นั้น ซึ่งถูกจัดเก็บอยู่ในพื้นที่ที่เรียกว่า Data Area.

การจัดเก็บ Start Cluster Number ภายใน Directory Entry

ตามที่แหล่งข้อมูลระบุ Directory Entry คือโครงสร้างข้อมูลขนาด 32 ไบต์. ภายใน 32 ไบต์นี้ หมายเลขคลัสเตอร์เริ่มต้นซึ่งเป็นตัวเลขขนาด 32 บิต จะไม่ได้ถูกเก็บไว้ในตำแหน่งเดียวต่อเนื่องกัน แต่จะถูก แบ่งออกเป็นสองส่วน เพื่อจัดเก็บในตำแหน่งที่ต่างกันภายในโครงสร้าง:

1. High 2 bytes of first cluster (2 ไบต์): ส่วนนี้เก็บข้อมูล 16 บิตบน (Higher 16 bits) ของหมายเลขคลัสเตอร์เริ่มต้น.

2. Low 2 bytes of first cluster (2 ไบต์): ส่วนนี้เก็บข้อมูล 16 บิตล่าง (Lower 16 bits) ของหมายเลขคลัสเตอร์เริ่มต้น.

ดังนั้น ในการที่จะได้หมายเลขคลัสเตอร์เริ่มต้นที่สมบูรณ์ขนาด 32 บิต นักวิเคราะห์จะต้องอ่านค่าจากทั้งสองส่วนนี้แล้วนำมารวมกัน.

ความสำคัญในบริบทของนิติวิทยาศาสตร์ดิสก์

ความสำคัญของ Start Cluster Number ในโครงสร้าง Directory Entry นั้นมีมิติที่ลึกซึ้งอย่างยิ่งสำหรับงานสืบสวนทางดิจิทัล:

• เป็นสะพานเชื่อมไปยังข้อมูลจริง: Start Cluster Number คือข้อมูลชิ้นสำคัญที่บอกระบบไฟล์ (และนักวิเคราะห์) ว่า "เนื้อหาของไฟล์นี้เริ่มต้นที่คลัสเตอร์หมายเลขใดใน Data Area". หากไม่มีข้อมูลนี้ ต่อให้มีข้อมูลเมตาดาต้าอื่นๆ เช่น ชื่อไฟล์หรือขนาดไฟล์ ก็จะไม่สามารถเข้าถึงเนื้อหาจริงของไฟล์ได้.

• กุญแจสำคัญในการกู้คืนไฟล์ที่ถูกลบ: นี่คือจุดที่สำคัญที่สุดในทางนิติวิทยาศาสตร์. เมื่อไฟล์ถูกลบ ไบต์แรกของ Directory Entry จะถูกเปลี่ยนเป็นค่า 0xE5 เพื่อระบุว่าไฟล์ถูกลบแล้ว. อย่างไรก็ตาม ข้อมูลส่วนที่เหลืออีก 31 ไบต์ ซึ่งรวมถึง High และ Low 2 bytes ของ Start Cluster Number มักจะยังคงอยู่เหมือนเดิม.

◦ ดังนั้น นักวิเคราะห์สามารถสแกนหา Entry ที่ขึ้นต้นด้วย 0xE5.

◦ จากนั้นทำการประกอบร่าง Start Cluster Number จากค่า High และ Low ที่ยังหลงเหลืออยู่.

◦ เมื่อได้หมายเลขคลัสเตอร์เริ่มต้นแล้ว ก็จะสามารถตามไปยังตำแหน่งเริ่มต้นของข้อมูลไฟล์ใน Data Area ได้โดยตรง เพื่อเริ่มต้นกระบวนการกู้คืนข้อมูล.

โดยสรุป Start Cluster Number ที่อยู่ใน Directory Entry Structure ไม่ได้เป็นเพียงข้อมูลทางเทคนิค แต่เป็น ร่องรอยดิจิทัลชิ้นสำคัญ ที่รอดพ้นจากการถูกทำลายในกระบวนการลบไฟล์ปกติของ FAT32. มันทำหน้าที่เป็น "แผนที่" ที่ยังคงอยู่ ทำให้นักวิเคราะห์สามารถค้นหาและกู้คืนข้อมูลที่ดูเหมือนจะสูญหายไปแล้วกลับคืนมาได้.

บทที่ 6

การเปรียบเทียบโดยตรงระหว่าง exFAT กับ FAT32

แหล่งข้อมูลได้เปรียบเทียบคุณสมบัติหลักของ exFAT กับ FAT32 โดยชี้ให้เห็นถึงความเหนือกว่าของ exFAT ในหลายด้าน:

• การรองรับขนาด: exFAT หรือที่เรียกว่า FAT64 ถูกออกแบบมาเพื่อรองรับอุปกรณ์จัดเก็บข้อมูลขนาดใหญ่ และสามารถจัดการกับ ขนาดโวลุ่ม (Volume) และขนาดไฟล์เดี่ยวที่ใหญ่กว่า ที่ FAT32 ไม่สามารถทำได้.

• ความยืดหยุ่นของโครงสร้าง: exFAT รองรับ Variable Sector Size (ขนาดเซกเตอร์ที่หลากหลาย ตั้งแต่ 512 ถึง 4096 ไบต์) และมีขนาดคลัสเตอร์สูงสุดที่ใหญ่กว่า.

• การจัดการไฟล์และไดเรกทอรี: exFAT สามารถรองรับไฟล์ในไดเรกทอรีย่อยได้จำนวนมากขึ้นอย่างมหาศาล (สูงสุด 2,796,202 ไฟล์) และรองรับ Unicode ซึ่งทำให้สามารถใช้ชื่อไฟล์ได้หลากหลายภาษามากขึ้น.

• สิทธิบัตร: exFAT เป็นเทคโนโลยีที่ได้รับการจดสิทธิบัตรโดย Microsoft.

โครงสร้างเชิงลึกของ exFAT ที่แสดงให้เห็นความแตกต่าง

1. Boot Region (พื้นที่สำหรับบูต):

◦ exFAT มีโครงสร้าง Volume Boot Record (VBR) ที่ซับซ้อนกว่า โดยประกอบด้วย Main Boot Region และ Backup Boot Region เพื่อความทนทานต่อความเสียหาย.

◦ VBR ของ exFAT ครอบคลุมหลายเซกเตอร์ (ตั้งแต่เซกเตอร์ 0 ถึง 11) ซึ่งรวมถึง Extended Boot Sector (เซกเตอร์ 1-8).

◦ ส่วนขยายนี้มีความสำคัญเพราะมี Extended BPB (BIOS Parameter Block) ซึ่งทำหน้าที่เก็บข้อมูลเพิ่มเติมที่จำเป็นสำหรับระบบไฟล์สมัยใหม่ เช่น GUID ของโวลุ่ม, ขนาดของ allocation unit, และ checksums ซึ่งไม่สามารถจัดเก็บใน BPB หลักได้.

2. FAT Region (พื้นที่ตารางจัดสรรไฟล์):

◦ exFAT ใช้ File Allocation Table (FAT) สองชุด (FAT #1 และ FAT #2).

◦ เหตุผลที่มี FAT สองชุดคือเพื่อใช้เป็น ข้อมูลสำรองในกรณีที่ชุดใดชุดหนึ่งเสียหายหรือเกิดข้อผิดพลาด และยังช่วยให้สามารถทำการวิเคราะห์เปรียบเทียบเพื่อตรวจสอบความสมบูรณ์ของระบบไฟล์ได้.

3. Data Region (พื้นที่จัดเก็บข้อมูล):

◦ เป็นส่วนที่ใช้เก็บข้อมูลจริงของไฟล์และไดเรกทอรี. พื้นที่นี้ประกอบด้วยชุดของคลัสเตอร์ (Cluster) ซึ่งเป็นหน่วยพื้นฐานในการจัดเก็บข้อมูล ที่เรียกว่า Cluster Heap.

◦ exFAT ใช้ระบบ Directory Entry ที่มีโครงสร้างหลากหลายเพื่อจัดการไฟล์และข้อมูลเมตาของโวลุ่ม. แต่ละ Entry มีขนาด 32 ไบต์และมีรหัสบอกประเภท (Entry Type). Directory Entry ที่สำคัญ ได้แก่:

▪ File Directory Entry: เก็บข้อมูลเมตาเกี่ยวกับไฟล์ เช่น คุณสมบัติของไฟล์ (attributes), เวลาที่สร้าง, แก้ไขล่าสุด และเข้าถึงล่าสุด.

▪ Stream Extension Entry: ให้ข้อมูลเพิ่มเติมเกี่ยวกับสตรีมข้อมูลของไฟล์ เช่น ตำแหน่งคลัสเตอร์แรกที่เก็บข้อมูลและขนาดข้อมูลจริง.

▪ File Name Extension Entry: ใช้เพื่อจัดเก็บชื่อไฟล์ที่ยาว ซึ่งเป็นคุณสมบัติที่สำคัญของ exFAT.

▪ Allocation Bitmap Directory Entry: ทำหน้าที่ชี้ไปยังบิตแมปที่ติดตามสถานะการใช้งานของคลัสเตอร์ใน Data Region ว่าคลัสเตอร์ใดถูกใช้งานแล้วหรือยังว่างอยู่.

▪ Up-Case Table Directory Entry: เก็บตารางอักขระตัวพิมพ์ใหญ่ เพื่อใช้ในการเปรียบเทียบชื่อไฟล์แบบไม่คำนึงถึงตัวพิมพ์ใหญ่-เล็ก (case-insensitive).

▪ Volume GUID Directory Entry: เก็บตัวระบุที่ไม่ซ้ำกันทั่วโลก (Globally Unique Identifier) สำหรับโวลุ่มนั้นๆ เพื่อให้สามารถระบุโวลุ่มได้อย่างแม่นยำ.

โดยสรุป แหล่งข้อมูลเหล่านี้อธิบายว่า exFAT ไม่ใช่แค่การขยายขีดจำกัดด้านขนาดของ FAT32 แต่ยังเป็นการออกแบบระบบไฟล์ใหม่ที่มีโครงสร้างที่ซับซ้อน ยืดหยุ่น และมี отказоустойчивость (fault tolerance) สูงกว่า ผ่านกลไกต่างๆ เช่น Backup Boot Region, FAT สองชุด, และระบบ Directory Entry ที่หลากหลาย ซึ่งทั้งหมดนี้ทำให้ exFAT เหมาะสมกับอุปกรณ์จัดเก็บข้อมูลสมัยใหม่ที่มีขนาดใหญ่และความต้องการที่ซับซ้อนมากขึ้น

รายการเปรียบเทียบหลักตามที่แหล่งข้อมูลระบุ

1. ข้อจำกัดด้านขนาดไฟล์และโวลุ่ม (File and Volume Size Limit)

◦ นี่คือจุดเปรียบเทียบที่สำคัญที่สุด แหล่งข้อมูลเน้นว่า exFAT (หรือที่เรียกว่า FAT64) ถูกสร้างขึ้นเพื่อ รองรับอุปกรณ์จัดเก็บข้อมูลขนาดใหญ่ (Large storage devices) และสามารถจัดการกับไฟล์เดี่ยวที่มีขนาดใหญ่กว่าที่ FAT32 จะทำได้ ซึ่งเป็นการแก้ปัญหาข้อจำกัดหลักของ FAT32 โดยตรง

2. ความเข้ากันได้ (Compatibility)

◦ แม้แหล่งข้อมูลจะไม่ได้ขยายความในส่วนนี้มากนัก แต่การระบุว่า "Compatibility" เป็นหนึ่งในหัวข้อเปรียบเทียบ ก็ชี้ให้เห็นว่าระบบไฟล์ทั้งสองอาจทำงานได้ดีบนอุปกรณ์หรือระบบปฏิบัติการที่แตกต่างกัน ซึ่งโดยทั่วไปแล้ว (ข้อมูลนี้นอกเหนือจากแหล่งข้อมูลที่ให้มา) FAT32 จะเข้ากันได้กับอุปกรณ์รุ่นเก่าและหลากหลายกว่า ในขณะที่ exFAT ถูกออกแบบมาสำหรับอุปกรณ์สมัยใหม่

3. ตารางการจัดสรรไฟล์ (File Allocation Tables)

◦ แหล่งข้อมูลระบุว่า "File allocation tables" เป็นอีกหนึ่งรายการเปรียบเทียบ และได้อธิบายเพิ่มเติมในส่วนของ exFAT ว่ามี FAT สองชุด (FAT #1 และ FAT #2) เหตุผลของการมีสองชุดคือเพื่อ ใช้เป็นข้อมูลสำรองในกรณีที่เกิดความเสียหายหรือข้อผิดพลาด และยังช่วยให้สามารถวิเคราะห์เปรียบเทียบเพื่อตรวจสอบความสมบูรณ์ของระบบไฟล์ได้ ซึ่งเป็นคุณสมบัติด้านความทนทานต่อความเสียหาย (fault tolerance) ที่เหนือกว่า

การเปรียบเทียบในเชิงโครงสร้างและคุณสมบัติเพิ่มเติม

นอกเหนือจากรายการเปรียบเทียบหลัก แหล่งข้อมูลยังให้รายละเอียดเชิงลึกที่แสดงให้เห็นความแตกต่างในบริบทที่กว้างขึ้น:

• การรองรับชื่อไฟล์: exFAT รองรับ Unicode ซึ่งหมายความว่าสามารถใช้ชื่อไฟล์ได้หลากหลายภาษามากกว่า FAT32 โครงสร้างภายในของ exFAT สนับสนุนสิ่งนี้ผ่าน File Name Extension Directory Entry ที่ออกแบบมาเพื่อจัดเก็บชื่อไฟล์แบบยาวโดยเฉพาะ นอกจากนี้ยังมี Up-Case Table Directory Entry เพื่อช่วยในการเปรียบเทียบชื่อไฟล์แบบไม่คำนึงถึงตัวพิมพ์ใหญ่-เล็ก (case-insensitive)

• ความยืดหยุ่นของโครงสร้าง: exFAT รองรับ Variable Sector Size (ขนาดเซกเตอร์ที่หลากหลายตั้งแต่ 512 ถึง 4096 ไบต์) และมี ขนาดคลัสเตอร์สูงสุด (Maximum cluster size) ที่ใหญ่กว่า FAT32 ทำให้สามารถปรับแต่งประสิทธิภาพให้เหมาะสมกับสื่อบันทึกข้อมูลประเภทต่างๆ ได้ดีกว่า

• การจัดการไดเรกทอรี: exFAT สามารถรองรับจำนวนไฟล์ในไดเรกทอรีย่อยได้เพิ่มขึ้นอย่างมหาศาล (สูงสุด 2,796,202 ไฟล์) ซึ่งเป็นข้อได้เปรียบอย่างมากสำหรับการจัดเก็บข้อมูลจำนวนมากในโฟลเดอร์เดียว

• ความเป็นเจ้าของ: exFAT เป็นเทคโนโลยีที่ ได้รับการจดสิทธิบัตรโดย Microsoft (MS Patents) ซึ่งเป็นข้อแตกต่างในเชิงธุรกิจและกฎหมายเมื่อเทียบกับ FAT32

โดยสรุป แหล่งข้อมูลนำเสนอ "รายการเปรียบเทียบ" เพื่อชี้ให้เห็นว่า exFAT ไม่ได้เป็นเพียงการขยายขนาดของ FAT32 แต่เป็นการออกแบบใหม่ที่แก้ไขข้อจำกัดพื้นฐานและเพิ่มคุณสมบัติที่ซับซ้อนและทันสมัยเข้ามา การเปรียบเทียบครอบคลุมตั้งแต่ข้อจำกัดด้านขนาด, การรองรับอักขระสากล, ความยืดหยุ่นของโครงสร้าง ไปจนถึงกลไกการทำงานภายใน เช่น การมี FAT สองชุดเพื่อความปลอดภัยของข้อมูล ซึ่งทั้งหมดนี้ทำให้ exFAT เป็นตัวเลือกที่เหนือกว่าสำหรับอุปกรณ์จัดเก็บข้อมูลในยุคปัจจุบัน

โครงสร้าง exFAT

Main Boot Region คือหนึ่งในสี่ส่วนประกอบหลักของโครงสร้างระบบไฟล์ exFAT ซึ่งทำหน้าที่เป็นจุดเริ่มต้นและเป็น "แผนที่หลัก" ของโวลุ่มทั้งหมด มันไม่ได้เป็นเพียงเซกเตอร์เดียว แต่เป็นกลุ่มของเซกเตอร์ที่เก็บข้อมูลสำคัญยิ่งยวดในการระบุตำแหน่งและคุณลักษณะของส่วนอื่นๆ ในระบบไฟล์

โครงสร้างโดยละเอียดของ Main Boot Region

Main Boot Region ประกอบด้วยหลายเซกเตอร์ ซึ่งแต่ละส่วนมีหน้าที่เฉพาะเจาะจง ดังนี้:

• Sector 0 (Boot Sector): นี่คือเซกเตอร์ที่สำคัญที่สุดและเป็นที่อยู่ของ Volume Boot Record (VBR) ภายใน Boot Sector ประกอบด้วย:

◦ Jump Instruction: คำสั่งเพื่อข้ามไปยังส่วนของ Boot Code

◦ File System Name: ชื่อระบบไฟล์ ซึ่งก็คือ "EXFAT"

◦ BIOS Parameter Block (BPB): โครงสร้างข้อมูลที่สำคัญที่สุด ซึ่งบรรจุพารามิเตอร์ต่างๆ ของโวลุ่ม เช่น ตำแหน่งของ FAT และ Data Region

◦ Boot Code: โปรแกรมที่ใช้ในการบูตระบบ

◦ End of Sector Marker (55 AA): ตัวระบุท้ายเซกเตอร์

• Sector 1-8 (Extended Boot Sector): เป็นเซกเตอร์ส่วนขยายที่สงวนไว้สำหรับ Boot Code เพิ่มเติม

• Sector 9 (OEM Parameter Record Sector): เซกเตอร์นี้อาจมีพารามิเตอร์ทางเทคนิคจากผู้ผลิต (Original Equipment Manufacturer) เพื่อปรับแต่งประสิทธิภาพของอุปกรณ์

• Sector 10 (Reserved Sector): เป็นเซกเตอร์ที่ถูกสงวนไว้ ไม่ได้ใช้งาน

• Sector 11 (Checksum Sector): ใช้สำหรับเก็บค่า Checksum เพื่อตรวจสอบความสมบูรณ์ของข้อมูลใน 11 เซกเตอร์แรกของ Main Boot Region

บทบาทของ Main Boot Region ในโครงสร้าง exFAT

Main Boot Region มีบทบาทสำคัญอย่างยิ่งในการเชื่อมโยงโครงสร้างทั้งหมดของ exFAT เข้าด้วยกัน โดยข้อมูลใน BPB (ซึ่งอยู่ใน Boot Sector) จะทำหน้าที่เป็นตัวชี้ (Pointer) ไปยังส่วนประกอบหลักอื่นๆ:

1. การระบุตำแหน่ง FAT Region: BPB ใน Main Boot Region จะมีฟิลด์ที่ชื่อว่า FAT Offset (ที่อยู่ 0x50) ซึ่งระบุตำแหน่งเริ่มต้นของ FAT Region FAT Region คือตารางที่ใช้ติดตามการจัดสรรพื้นที่ (Allocation Status) ของคลัสเตอร์ทั้งหมดในโวลุ่ม

2. การระบุตำแหน่ง Data Region (Cluster Heap): BPB จะมีฟิลด์ที่ชื่อว่า Cluster Heap Offset (ที่อยู่ 0x58) ซึ่งชี้ไปยังตำแหน่งเริ่มต้นของ Data Region Data Region หรือที่เรียกว่า Cluster Heap เป็นพื้นที่ที่ใช้จัดเก็บข้อมูลของไฟล์และไดเรกทอรีต่างๆ จริงๆ

3. การสำรองข้อมูลเพื่อความเสถียร: โครงสร้าง exFAT มีการออกแบบให้มี Backup Boot Region ซึ่งเป็นสำเนาของ Main Boot Region ทั้งหมด โดยจะถูกเก็บไว้ในเซกเตอร์ที่ 12 ถึง 23 การมีสำเนานี้ช่วยให้สามารถกู้คืนระบบไฟล์ได้ในกรณีที่ Main Boot Region เกิดความเสียหาย

โดยสรุป Main Boot Region คือรากฐานของโครงสร้าง exFAT มันบรรจุข้อมูลการกำหนดค่าที่สำคัญที่สุดไว้ใน VBR และ BPB ซึ่งจำเป็นต่อการทำความเข้าใจและเข้าถึงส่วนอื่นๆ ของระบบไฟล์

Backup Boot Region เป็นหนึ่งในสี่ส่วนประกอบหลักของโครงสร้างระบบไฟล์ exFAT มันทำหน้าที่เป็น สำเนาสำรอง (backup copy) ของ Main Boot Region โดยมีวัตถุประสงค์หลักเพื่อ ความเสถียรและการกู้คืนข้อมูล ในกรณีที่ส่วนหลักเกิดความเสียหาย

สำเนาของ Boot Sector (จาก Sector 0) ซึ่งมี Jump Instruction, ชื่อระบบไฟล์ "EXFAT", และที่สำคัญที่สุดคือ BIOS Parameter Block (BPB)

◦ สำเนาของ Extended Boot Sectors (จาก Sector 1-8)

◦ สำเนาของ OEM Parameter Record Sector (จาก Sector 9)

◦ สำเนาของ Reserved Sector (จาก Sector 10)

◦ สำเนาของ Checksum Sector (จาก Sector 11) เพื่อตรวจสอบความสมบูรณ์ของข้อมูลในบริเวณนี้

FAT Region หรือ File Allocation Table Region คือหนึ่งในสี่ส่วนประกอบหลักของโครงสร้าง exFAT มันทำหน้าที่เปรียบเสมือน "สารบัญ" หรือ "แผนที่" ที่สำคัญอย่างยิ่งในการติดตามการจัดสรรพื้นที่ของไฟล์และไดเรกทอรี ภายใน Data Region หากปราศจาก FAT Region ข้อมูลที่เก็บอยู่ใน Data Region ก็จะเป็นเพียงกลุ่มก้อนของข้อมูลที่ไม่สามารถระบุได้ว่าเป็นของไฟล์ใด

1. เพื่อการสำรองข้อมูล (Backup): ในกรณีที่ FAT #1 เกิดความเสียหายหรือข้อมูลผิดเพี้ยน (corruption) ระบบจะยังสามารถใช้ FAT #2 เพื่อกู้คืนข้อมูลและรักษาความสมบูรณ์ของระบบไฟล์ได้

2. เพื่อการวิเคราะห์เปรียบเทียบ (Comparative Analysis): การมีสำเนาสองชุดช่วยให้นักวิเคราะห์สามารถเปรียบเทียบข้อมูลเพื่อตรวจสอบความผิดปกติหรือการเปลี่ยนแปลงที่อาจเกิดขึ้นได้

Data Region หรือที่เรียกว่า Cluster Heap เป็นหนึ่งในสี่ส่วนประกอบหลักของโครงสร้างระบบไฟล์ exFAT และถือเป็นส่วนที่สำคัญที่สุด เพราะเป็น บริเวณที่ใช้จัดเก็บข้อมูลที่แท้จริงทั้งหมด ไม่ว่าจะเป็นเนื้อหาของไฟล์, ข้อมูลไดเรกทอรี, และโครงสร้างเมทาดาทาอื่นๆ ที่จำเป็นต่อการทำงานของระบบไฟล์

การจัดเก็บข้อมูล (Storing Data): เป็นพื้นที่หลักสำหรับเก็บเนื้อหาของไฟล์และข้อมูลไดเรกทอรีต่างๆ

• การจัดการคลัสเตอร์ (Cluster Management): โครงสร้างภายใน Data Region ถูกออกแบบมาเพื่อจัดการ คลัสเตอร์ (Cluster) ซึ่งเป็นหน่วยพื้นฐานในการจัดสรรพื้นที่สำหรับเก็บข้อมูล

• การใช้พื้นที่อย่างมีประสิทธิภาพ (Efficient use of space): การจัดการผ่าน Cluster Heap ช่วยให้สามารถจัดสรรและยกเลิกการจัดสรรพื้นที่ได้อย่างมีประสิทธิภาพ

• ความสมบูรณ์ของระบบไฟล์ (File System Integrity): โครงสร้างภายใน Data Region ช่วยรักษาความสมบูรณ์ของข้อมูลและระบบไฟล์โดยรวม

ครงสร้างและตำแหน่งของ VBR ใน Main Boot Region

ในระบบไฟล์ exFAT, VBR ไม่ได้จำกัดอยู่แค่ในเซกเตอร์เดียว แต่เป็นส่วนหนึ่งของบริเวณที่ใหญ่กว่าเรียกว่า Main Boot Region ซึ่งเป็นหนึ่งในสี่ส่วนประกอบหลักของโครงสร้าง exFAT บริเวณนี้ประกอบด้วยหลายเซกเตอร์ที่มีหน้าที่เฉพาะเจาะจง:

• Sector 0 (Boot Sector): เป็นเซกเตอร์หลักและเป็นที่อยู่ของ VBR ภายในประกอบด้วยข้อมูลสำคัญเช่น:

◦ Jump Instruction: คำสั่งสำหรับข้ามไปยัง Boot Code

◦ File System Name: ระบุชื่อระบบไฟล์ ซึ่งก็คือ "EXFAT"

◦ BIOS Parameter Block (BPB): โครงสร้างข้อมูลที่สำคัญที่สุดซึ่งบรรจุพารามิเตอร์ของโวลุ่ม

◦ Boot Code: โปรแกรมสำหรับบูตระบบ

◦ End of Sector Marker (55 AA): ตัวระบุท้ายเซกเตอร์

• Sector 1-8 (Extended Boot Sector): เซกเตอร์ส่วนขยายสำหรับ Boot Code หรือข้อมูลเพิ่มเติม

• Sector 9 (OEM Parameter Record Sector): อาจมีพารามิเตอร์ทางเทคนิคจากผู้ผลิต (OEM) เพื่อปรับแต่งประสิทธิภาพ

• Sector 10 (Reserved Sector): เซกเตอร์ที่ถูกสำรองไว้

• Sector 11 (Checksum Sector): ใช้สำหรับตรวจสอบความสมบูรณ์ของข้อมูลใน 11 เซกเตอร์แรก

นอกจากนี้ exFAT ยังมี Backup Boot Region ซึ่งเป็นสำเนาของ Main Boot Region อยู่ในเซกเตอร์ที่ 12-23

บทบาทและความสำคัญของ BPB และ Extended BPB

BPB คือโครงสร้างข้อมูลที่สำคัญซึ่งอยู่ตอนต้นของระบบไฟล์ ทำหน้าที่ให้ข้อมูลที่จำเป็นในการอ่านและทำความเข้าใจอุปกรณ์จัดเก็บข้อมูลนั้นๆ สำหรับ exFAT มีการใช้ Extended BPB ด้วย

ข้อมูลสำคัญใน BPB สำหรับการวิเคราะห์

BPB ให้ข้อมูลที่เป็นกุญแจสำคัญในการระบุตำแหน่งและขนาดของโครงสร้างหลักอื่นๆ ใน exFAT ซึ่งจำเป็นอย่างยิ่งต่อการวิเคราะห์เชิงฟอเรนซิกส์ ข้อมูลเหล่านี้ได้แก่:

• Partition Offset (ที่อยู่ 0x40): ตำแหน่งเริ่มต้นของพาร์ติชัน

• Volume Length (ที่อยู่ 0x48): ขนาดความยาวทั้งหมดของโวลุ่ม

• FAT Offset (ที่อยู่ 0x50): ตำแหน่งเริ่มต้นของตาราง File Allocation Table (FAT) ซึ่งใช้ติดตามการจัดสรรพื้นที่ของไฟล์

• FAT Length (ที่อยู่ 0x54): ขนาดความยาวของตาราง FAT

• Cluster Heap Offset (ที่อยู่ 0x58): ตำแหน่งเริ่มต้นของ Data Region (หรือ Cluster Heap) ซึ่งเป็นบริเวณที่จัดเก็บข้อมูลไฟล์และไดเรกทอรีจริงๆ

• Cluster Count (ที่อยู่ 0x5C): จำนวนคลัสเตอร์ทั้งหมดในโวลุ่ม

• Root Directory First Cluster (ที่อยู่ 0x60): ตำแหน่งคลัสเตอร์เริ่มต้นของ Root Directory

• Bytes Per Sector (ที่อยู่ 0x6C) และ Sectors Per Cluster (ที่อยู่ 0x6D): ข้อมูลขนาดเซกเตอร์และจำนวนเซกเตอร์ต่อคลัสเตอร์ ซึ่งใช้ในการคำนวณตำแหน่งต่างๆ

1. การวิเคราะห์กระบวนการสร้างไฟล์ (File Creation Process)

เมื่อมีการสร้างไฟล์ใหม่ในระบบ exFAT จะเกิดการเปลี่ยนแปลงในส่วนต่างๆ ของระบบไฟล์ ซึ่งเป็นร่องรอยที่นักวิเคราะห์ฟอเรนซิกส์สามารถตรวจสอบได้ กระบวนการนี้ประกอบด้วยขั้นตอนหลักดังนี้:

1. สำรวจคลัสเตอร์ที่ว่าง (Explore available clusters): ระบบจะตรวจสอบ Allocation Bitmap เพื่อค้นหาคลัสเตอร์ที่ยังว่างและพร้อมใช้งาน Allocation Bitmap นี้ทำหน้าที่เป็นแผนที่สถานะการใช้งานของทุกคลัสเตอร์ใน Data Region

2. สร้าง Directory Entry ใหม่ (Create a new directory entry): ระบบจะสร้างชุดของ Directory Entry เพื่อจัดเก็บเมทาดาทาของไฟล์ใหม่ โดยประกอบด้วย:

◦ File Directory Entry: บันทึกข้อมูลเมทาดาทาหลัก เช่น แอตทริบิวต์ของไฟล์ (ซ่อน, อ่านอย่างเดียว), และ timestamps ที่สำคัญ (เวลาสร้าง, แก้ไขล่าสุด, เข้าถึงล่าสุด) ซึ่งเป็นหลักฐานที่สำคัญอย่างยิ่งในการระบุลำดับเวลาของเหตุการณ์

◦ Stream Extension Entry: ระบุตำแหน่งคลัสเตอร์แรกที่ข้อมูลไฟล์จะถูกจัดเก็บ (First Cluster) และขนาดข้อมูลที่แท้จริง (Valid Data Length)

◦ File Name Extension Entry: ใช้สำหรับจัดเก็บชื่อไฟล์ ซึ่งอาจมีหนึ่งหรือหลาย Entry ขึ้นอยู่กับความยาวของชื่อไฟล์ โดยใช้การเข้ารหัสแบบ UTF-16

3. อัปเดต Allocation Bitmap (Update Allocation Bitmap): คลัสเตอร์ที่ถูกเลือกใช้งานจะถูกอัปเดตสถานะใน Allocation Bitmap จาก "ว่าง" (free) เป็น "ใช้งานอยู่" (in-use) การเปลี่ยนแปลงนี้เป็นการยืนยันว่าพื้นที่ถูกจัดสรรให้กับไฟล์ใหม่แล้ว

4. บันทึกข้อมูล (Save Data): เนื้อหาของไฟล์จะถูกเขียนลงในคลัสเตอร์ที่ถูกจัดสรรไว้ใน Data Region (Cluster Heap)

ในมุมมองฟอเรนซิกส์: กระบวนการนี้สร้างหลักฐานที่ชัดเจน ทั้งเมทาดาทาที่สมบูรณ์ใน Directory Entries (โดยเฉพาะ timestamps) และการเปลี่ยนแปลงสถานะใน Allocation Bitmap ซึ่งสามารถใช้ยืนยันการมีอยู่และการสร้างไฟล์ ณ เวลาที่ระบุได้

2. การวิเคราะห์กระบวนการลบไฟล์ (File Deletion Process)

กระบวนการลบไฟล์ใน exFAT ไม่ได้เป็นการลบข้อมูลออกจากดิสก์ในทันที แต่เป็นการเปลี่ยนแปลงเมทาดาทาเพื่อทำให้ไฟล์นั้นไม่สามารถเข้าถึงได้อีกต่อไป ซึ่งทิ้งร่องรอยสำคัญไว้ให้นักวิเคราะห์ตรวจสอบ

1. ค้นหา Directory Entry (Browse Directory Entry): ระบบจะค้นหาชุดของ Directory Entry ที่เกี่ยวข้องกับไฟล์ที่จะลบ

2. ลบ Directory Entry (Delete Directory Entry): Directory Entry ที่เกี่ยวข้อง (File, Stream Extension, File Name) จะถูก "ทำเครื่องหมายว่าถูกลบ" (marked as deleted) ข้อมูลเมทาดาทาเดิมส่วนใหญ่ยังคงอยู่ แต่ระบบไฟล์จะไม่แสดงรายการไฟล์นี้อีกต่อไป

3. ปล่อยคลัสเตอร์และอัปเดต Allocation Bitmap (Release clusters & Update Allocation Bitmap): คลัสเตอร์ที่เคยใช้เก็บข้อมูลของไฟล์จะถูกปล่อยให้เป็นอิสระ โดยการอัปเดตสถานะใน Allocation Bitmap กลับไปเป็น "ว่าง" (free) Crucially, the actual data within these clusters is not erased at this stage.

4. รักษาสภาพความสมบูรณ์ (Maintain integrity): ระบบจะปรับปรุงโครงสร้างเพื่อให้แน่ใจว่าการลบเสร็จสมบูรณ์และไม่มีความขัดแย้งเกิดขึ้น

ในมุมมองฟอเรนซิกส์: นี่คือจุดที่สำคัญที่สุด ข้อมูลไฟล์ที่แท้จริงยังคงอยู่ใน Data Region และ Directory Entry ที่ถูกลบก็ยังคงอยู่เช่นกัน ทำให้มีโอกาสสูงในการกู้คืนไฟล์ตราบใดที่พื้นที่คลัสเตอร์นั้นยังไม่ถูกเขียนทับด้วยข้อมูลใหม่

--------------------------------------------------------------------------------

3. การวิเคราะห์กระบวนการกู้คืนไฟล์ (File Recovery Process)

การกู้คืนไฟล์ที่ถูกลบเป็นกระบวนการย้อนกลับของการลบ โดยอาศัยร่องรอยที่ยังหลงเหลืออยู่บนดิสก์

1. ค้นหา Directory Entry ที่ถูกลบ (Find deleted directory entries): เครื่องมือฟอเรนซิกส์จะสแกนหา Directory Entry ที่ถูกทำเครื่องหมายว่าลบไปแล้ว แต่ยังคงมีข้อมูลเมทาดาทาที่สมบูรณ์อยู่

2. ตรวจสอบ Allocation Bitmap (Check the Allocation Bitmap): นักวิเคราะห์จะตรวจสอบว่าคลัสเตอร์ที่ระบุไว้ใน Stream Extension Entry ของไฟล์ที่ถูกลบนั้น ยังคงมีสถานะเป็น "ว่าง" ใน Allocation Bitmap หรือไม่ หากยังว่างอยู่ แสดงว่าข้อมูลเดิมอาจยังไม่ถูกเขียนทับ

3. กู้คืน Directory Entry และอัปเดต Bitmap (Restore the Directory Entry & Update Allocation Bitmap): ทำการยกเลิกเครื่องหมาย "ถูกลบ" บน Directory Entry และอัปเดตสถานะของคลัสเตอร์ที่เกี่ยวข้องใน Allocation Bitmap กลับไปเป็น "ใช้งานอยู่"

4. กู้คืนการเข้าถึงไฟล์ (Restore file accessibility): เมื่อ Directory Entry และ Allocation Bitmap ถูกกู้คืนแล้ว ระบบไฟล์จะสามารถเชื่อมโยงเมทาดาทากลับไปยังข้อมูลในคลัสเตอร์ได้อีกครั้ง ทำให้ไฟล์กลับมาเข้าถึงได้
