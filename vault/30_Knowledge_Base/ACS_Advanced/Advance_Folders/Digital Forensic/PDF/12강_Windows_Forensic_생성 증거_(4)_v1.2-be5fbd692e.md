What is an event log?01
Event Log
Definition
'Event' means 'incident' or 'occurrence' and 'log' means 'record’
“Event Log” refers to a file or database that sequentially records events that occur on
a computer system, network equipment, software application, etc.
Logs contain detailed information about a variety of events, including system status,
errors, warnings, informational messages, and security-related incidents
Extensions and
paths
.evt : used in Windows 2000,XP,Server2003
 %SystemRoot%System32%config
 .evtx : introduced since Windows Vista
 %SystemRoot%System32\winevt\Logs
Where it's
used
Event logs are widely used by system administrators to monitor the normal
operating status of their systems and diagnose problems
Security professionals also utilize event logs to investigate, audit, and monitor
security incidents
Application developers use event logs to debug errors in their applications and
analyze user usage patterns
Digital forensics
perspective
By analyzing event logs, forensic analysts can track unauthorized access to a system,
execution of malicious code, user activity history, system errors, and other security-
related incidents
Event logs provide critical evidence that can reveal what happened on a system,
when it happened, and can be used as evidence in legal cases

Application whitelisting: Application whitelisting is a security mechanism that ensures that only authorized software is allowed to run
on a system. Application events that are blocked from running often indicate malware or unauthorized software attempts, and can be
used to proactively block security threats. Windows' Software Restriction Policy (SRP) and AppLocker provide this whitelisting

Application crashes: Application crashes indicate system stability issues, and it's important to determine the cause of the crash and

System or service failures: Failure of a system or service indicates an abnormal situation, and repeated service failures may signal a
targeted attack by an attacker Consecutive failures of a service should be investigated quickly by system administrators, and these
failure event logs provide critical information to maintain the security and stability of the system
Windows Firewall: Windows Firewall serves as the first line of defense for network security, and monitoring changes in its status is a
key part of security management. If the firewall is disabled or changed, it indicates a possible security threat or policy violation, so it is
important to collect and analyze relevant event logs
Event log clearing: Deletion of event logs is rare in normal operations and is most likely done for malicious purposes If event logs are
cleared, this can be seen as an attempt by an attacker to hide traces of their activity Centralized log collection is an effective way to
prevent such attempts and make it more difficult for attackers to cover their tracks Additionally, deploying redundant collection servers
can reduce concerns about single points of failure

File Header
Purpose: Located at the beginning of the .evtx file and contains
metadata about the file
Components: information such as file version, file size, number

needed to identify if the file is valid and what kind of log file it is
Chunk Header
Purpose: Each chunk represents a block of event log data, and
the chunk header contains the metadata for that chunk
Components: Number of records within the chunk, start and
end times of the chunk, identifiers of the first and last records
within the chunk, etc. Used to navigate and access data within
the chunk
Record 1~N
Purpose: Contains the actual event log data, each record
contains information about an individual event
Components: Event ID, creation time, source that created the
event, event message, and event data in XML format. Each
record has a unique identifier so it can be referenced individually

Signature (“ElfFile”): This is a unique identifier that indicates the .evtx file is a
Windows event log file. All .evtx files start with this signature
First chunk number and last chunk number: These are the range of chunks
within the file where the event log was written. A chunk is a block that

chronological order of the log data
Next record identifier: A unique identifier of the next event log record to be
written within the file The identifier helps to ensure that each event log record
is uniquely identified
Header Size and Header Block Size: These indicate the byte size and number of
blocks occupied by the header portion of the .evtx file, which is important for
understanding and analyzing the structure of the file
Minor Version and Major Version: This is the version of the .evtx file format,

Chunk count: This is the total number of chunks contained within the file. Each

rough estimate of the size of the file and the amount of log data
Empty value (reserved area): This area is reserved for future use and has no special

File flags: Flags that indicate the status and characteristics of a file, for example,

of data in the file header, the CRC value checks to see if the file header is

What is a UUID
An event record Universally Unique Identifier (UUID) is a 128-bit number that is
assigned to uniquely identify each event record
Because UUIDs are randomly generated, they are extremely unlikely to be duplicated,
even if they are generated anywhere in the world
The chunk header stores the UUIDs for the first and last event records within the
chunk
Ensures order of creation of event records and allows each record to be referenced
individually
For example, the UUID of the last record in chunk1 matches the UUID of the first
record in chunk2
UUID matching allows you to verify connectivity between chunks and analyze the
entire event log sequentially 13

Checksum
A small piece of data derived from a block of data (e.g., a file, packet) that provides a simple
summary of the original data that can be calculated through simple operations such as
summing each byte of the data
Usually calculated before data is transmitted or stored, and recalculated at the receiving end
using the same checksum calculation method
If the two checksum values match, the data is assumed to have been transmitted or stored
correctly
If there is a mismatch, it is possible that data errors or tampering has occurred.occurred
Cyclic Redundancy Check (CRC)
More complex and reliable techniques used to detect changes in data
A fixed-length number calculated using advanced mathematical algorithms on blocks of data
Calculated by treating the data as a polynomial of constant length and dividing it by another
predefined polynomial to get the remainder
On the receiving end of the data, the same CRC calculation is performed, verifying that the
calculated CRC value matches the transmitted CRC value
