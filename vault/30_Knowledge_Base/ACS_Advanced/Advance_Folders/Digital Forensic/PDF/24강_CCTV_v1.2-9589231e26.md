IDIS File System
The IDIS DVR filesystem consists of a 'root block' and
several 'video data blocks’.
The root block is the starting point of the filesystem,
starting at the address 0x80100000, but for the sake of
simplicity, we will refer to it as 0x00 in this paper.
The root block contains the index information for each
data block, and subsequent data blocks store the video
data.
All blocks are set to 0x10000000 bytes in size, resulting
in a uniformly sized block structure.

IDIS File System
Shows the root block structure within the IDIS G2FDb file system.
Contains index information for each block of video data.
Has the signature "This is G2FDb Storage Magic" at a specific location
(0x500000) inside the root block. This signature acts as an identifier for
the file system and is the starting point for pointing to index information
for all video data blocks that exist within the file system.
Root block indexes exist in the file system in the same way as regular
image data blocks, with each block index being 64 bytes in size. The index
information starts with the index for the root block, followed by the
indexes for the blocks that contain the actual video information. Each
block index contains detailed information about that block, with the first
byte of the index indicating the type of block.
Block Types
0x00: Unallocated Block
0x01: Root Block
0x05: Video Data Block
0x20: Block with recorded first and last recording times

IDIS G2FDb File System Structure
1. Video header set area: Contains 32 bytes of headers for all videos in that block
2. Video header: The video header contains the following information
- Time information, data size
- Video group, channel number
- Frame type, data location
3. Time information: 4 bytes of time information indicates the year, month, day, hour, minute, and second,
calculated based on 1970
4. Data size: Indicates the size of the frame, equal to the data size value minus 0x23
5. Video groups: Actual video data is divided into frame units, each of which is composed of video groups
6. Channel number: The channel number indicates the camera channel stored within that video data block.
7. Frame type: The frame type is represented by 0x00 for I-Frame and 0x01 for P-Frame.
8. Data location: The area of data within each data block where the corresponding frame is located.
9. Camera channel information: Indicates the actual camera channel number, which is one greater than the
camera channel.

Deep Learning Models
ResNet 50
What is ResNet 50
A type of Residual Networks (ResNets) that facilitates the training of deep neural networks, a model widely
used in image recognition and classification tasks.
Key features and innovations
Residual Learning Framework: ResNet50 is structured to learn F(x) = H(x) - x, which is the difference in output
over input x, given the function to be learned, H(x).This allows the neural network to learn "residuals",
mitigating the learning difficulties that can occur as the network grows deeper.
Skip Connections / Shortcut Connections: ResNet50 uses skip connections, where the input of a layer is added
directly to the output, skipping a few layers. This approach reduces the vanishing/exploding gradient problem
that can occur in deep networks.
50 Layers Deep: ResNet50 has a total of 50 layers, consisting of multiple 3x3 convolutional layers with shortcut
connections via identity mapping. This structure prevents performance degradation as the model grows deeper
and allows for more accurate learning.
Wide Usage: ResNet50 has become the default model for a variety of computer vision tasks, including image
classification, object detection, and segmentation. This is because its pre-trained weights make it easy to adapt
to different datasets and tasks.
Performance
ResNet50 achieves high accuracy on the task of classifying 1.2 million images with 1,000 classes from the
ImageNet dataset. This model shows that performance does not improve with depth, but rather that optimal
performance can be achieved at the right depth. The introduction of ResNets, such as ResNet50, significantly
changed the way deep learning models are designed and inspired many subsequent studies and models.

Key Features
Balancing speed and accuracy: It is fast enough for real-time processing while maintaining
high accuracy. This has led to applications in real-time video streaming, traffic surveillance,
security systems, and more.
Analyzes the entire image: YOLO detects objects by analyzing the entire image at once, rather
than breaking it down into individual parts. This approach reduces background errors and
speeds up processing.
Using a Single Neural Network: Uses a single Convolutional Neural Network (CNN) to
simultaneously predict the location and classification of objects. This increases the efficiency of
the algorithm and simplifies its implementation.
How it works
Grid segmentation: YOLO divides the image into a grid of equal size, with each grid cell
responsible for predicting the likelihood of an object being present in that part of the image.
Bounding boxes and class prediction: Each grid cell predicts a number of bounding boxes and
the class probabilities of the objects they might contain. The bounding boxes define the
position and size of the objects.
Confidence score: Each bounding box has a confidence score, which is a combination of the
probability that the box contains an object and the predicted class probability.
Non-maximum Suppression (NMS): Multiple bounding boxes may detect the same object over
and over again. NMS keeps the most reliable of these boxes and removes the rest to clean up
the final detection result.
You Only Look Once (YOLO)
One of the most popular deep learning-based algorithms
in the field of object detection. The main feature of YOLO
is that it detects and classifies objects by looking at the
entire image at once. It allows you to quickly and
accurately identify multiple objects in an image and their
locations.
